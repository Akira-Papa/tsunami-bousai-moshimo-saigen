# 内陸地点のネスト計算（2026-09-24）

## 依頼
あきらパパ様から「名古屋駅などを選ぶと『周囲4km以内に海が見つかりませんでした』で選べない。どこでも津波がどう来るかを見られるようにして」とのご依頼。

## 方式：二段の一方向ネスト
| 段 | 範囲 | 格子 | 中身 |
|---|---|---|---|
| 広域 | 最大20km四方（名古屋駅で14km四方） | 1024²（約14m） | 海 → 港 → 運河・川 → 市街地。建物は壁にせず、粗度で表す（固い建物の割合に応じて n = 0.045〜0.09）。防潮壁（z14の「堤防等に接する」線）と満潮位、越流したら破堤、の条件は1段計算と同じ |
| 詳細 | 地点の周り1.5km四方 | 768²（約2m） | 建物を壁として扱う従来の計算。縁から70mの帯で、広域の水位（η）と流速に緩和する |

- 広域の造波帯は範囲の4%の幅にし、緩和時間を2.5秒と短くした。小さな港の水域だけでは市街地全体の浸水を賄えず、海岸の水位が1m前後で止まっていたため。
- 開けた海（陸から150m以上離れた水面）の先に、海を3.5km含める。
- 詳細の格子は、広域の水の先端が地点から「詳細の範囲＋600m」以内に来るまで計算を止め、時計だけを進める（数十分間は広域だけを計算する）。
- 内陸の地点では、水位が高い時間を60分にした（全体で約90分）。陸の浸水は、海の水位が高い間は広がり続けるため。
- 視点に「広域」を追加。海から地点までを一望できる。既定の再生速度は×60。
- 名古屋市の内陸の区（中村区など）でも、既定値は名古屋港と同じ（満潮位 T.P.+1.2m、防潮壁 T.P.+4.6m）にした。水はこの防潮壁を越えて入ってくるため。

## 検証（ヘッドレスChromeで実際の画面を撮影）
| 地点 | 広域 | 結果 |
|---|---|---|
| 名古屋駅（中村区 名駅一丁目） | 14km四方 | 約50分後の水の先端は約6.0km手前。港周辺のゼロメートル地帯に浸水が広がるが、駅には届かない（公式の100m集約でも浸水セルなし） |
| 中川区 富田町 | 広域あり | 約88分後の水の先端は約1.3km手前。詳細の格子は計算を開始したが、この時点では未到達（公式の100m集約は2.6m） |
| 名古屋港 港町（1段計算） | — | ここの最大1.65m。変更前と同じで、退行なし |

- 単体テスト3本は合格。地点を3回続けて選び直しても、GPUエラーは0件。
- 富田町で公式と差がある主な理由は、計算時間（公式は数時間）と入力波の形（一様な長波）の違いと考えられる（未検証）。

## 途中で見つけて直したもの
- 広域に含めた海が狭すぎた：港の小さな水域だけで、海岸の水位が1.1〜1.4mで止まっていた。海3.5kmを含め、造波帯を強化して解決。
- `relaxW` の定義順のバグで、読み込み中にエラー（Cannot access 'L' before initialization）。
- 遠景の縞模様：固定の near 0.5m と far 49km で深度の精度が足りなかった。near を視距離の0.25%に連動させた。
- テスト用の画像保存関数（`__t.shot`、別のレンダーターゲットへ描き直す）は広域表示で縞になるが、実際の画面は正常。検証はページのスクリーンショットで行う。
