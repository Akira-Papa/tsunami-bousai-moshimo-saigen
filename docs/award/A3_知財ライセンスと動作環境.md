- アプリ本体に、第三者の画像・音楽・3Dモデルは含まれていません（`src/`・`public/` を検索して確認。ファビコンは `index.html` 内の自作 SVG）。

共通の規約は「国土地理院コンテンツ利用規約」（令和7年11月20日改正）です。本文より引用します。

- 規約 URL：https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html

- 出典記載例：「出典：国土地理院ウェブサイト　（当該ページのURL）」

## 4. 動作環境（応募フォーム用・詳しい版）

### 4-1. ブラウザ

WebGPU が必要です（WebGL では動きません。非対応の端末では「この端末では再現を表示できません」と自治体のハザードマップへの案内を表示します）。

| ブラウザ | 対応 | 根拠 |
|---|---|---|
| Google Chrome / Microsoft Edge 113 以降（Windows・macOS・ChromeOS） | 対応 | Chrome for Developers「This initial release of WebGPU was made available in Chrome 113, on ChromeOS devices with Vulkan support, Windows devices with Direct3D 12 support, and macOS.」 |
| Chrome（Android 12 以降、Qualcomm・ARM の GPU） | Chrome 121 以降で WebGPU に対応 | 同ページ「Android support was later in Chrome 121 on devices running Android 12 and greater powered by Qualcomm and ARM GPUs.」 |
| Safari 26 以降（macOS Tahoe 26・iOS 26・iPadOS 26） | 対応 | 同ページ「WebGPU shipped in Firefox 141 on Windows and Safari 26」 |
| Firefox 141 以降（Windows） | WebGPU は対応。本作品での動作は未確認 | 同上 |
| Linux の Chrome | 同ページで「Linux and expanded support for existing platforms is coming soon.」。推奨外 | 同上 |

- 審査での推奨：**PC の最新版 Google Chrome**（開発時の検証環境）。

### 4-2. 端末性能の目安

未実測です。コードの確保量から見積もった GPU メモリの下限の目安と、推奨の考え方を書きます。**実測値は A10 の品質確認で確定させ、ここを書き換えてください。**

| 計算の細かさ | 格子 | 1マス | GPUメモリの目安（コードからの概算） |
|---|---|---|---|
| 軽量 | 512² | 約3m | 約0.13GB |
| 標準（PCの既定） | 768² | 約2m | 約0.23GB |
| 高精細 | 1024² | 約1.5m | 約0.4GB |
| 内陸の地点（ネスト計算） | 上の格子＋広域 768²/1024² | 広域は約10〜14m | 上に約0.2〜0.3GB を加算 |

- 概算の内訳：1マスあたり状態・地形・付随場の vec4（f32）バッファ10本＝160バイト、描画用の半精度テクスチャ3枚、地面と水面のメッシュ2枚。航空写真テクスチャ 3072²（高精細は 4096²）、飛沫粒子 2^17 個。ブラウザ側のメモリ（JavaScript の配列）も同程度使います。
- 推奨の目安（暫定）：Apple Silicon の Mac、または独立 GPU か最近の内蔵 GPU を持つ Windows PC、メモリ 8GB 以上。性能が足りない場合は、表示解像度と1フレームあたりの計算回数を自動で下げ、約30fps を保とうとします（`src/main.js` の適応制御）。
- 画面の右下に「fps・格子・実効の再生速度」を表示するので、審査員が性能を確認できます。

### 4-3. 通信

- 地形（標高タイル）・航空写真・地図・住所検索・建物（PLATEAU の PMTiles、地理院ベクトルタイル）を、実行時にインターネットから取得します。1地点あたり数十〜百数十枚のタイルを読みます。
- 取得先：`cyberjapandata.gsi.go.jp`、`msearch.gsi.go.jp`、`mreversegeocoder.gsi.go.jp`、`shiworks.xsrv.jp`（PLATEAU の PMTiles。A1 の公式データに切り替わると同じサイト内の静的ファイルになる予定）、`fonts.googleapis.com`。
- 社内ネットワーク等でこれらが遮断されていると読み込めません。その場合は URL に `?demo=1` を付けると、通信なしの合成の港町で動きます。
- PLATEAU の配信元に届かないときは、自動で国土地理院の建物（種別から高さを推定）に切り替えて続行します。

### 4-4. スマートフォン

- 画面の短い辺が 700px 未満の端末では、計算の細かさを自動で「軽量（格子 512²）」にします（`src/main.js`）。
- WebGPU が使えるのは、iPhone・iPad は iOS/iPadOS 26 以降の Safari、Android は Android 12 以降の Chrome 121 以降（Qualcomm・ARM の GPU）です。
- 実機での動作確認は A10 の担当です。確認できた機種があれば追記し、確認できなければ「PC を推奨」と書いてください。

### 4-5. 審査員が確認する手順

1. PC の Google Chrome で https://share.akirafunakoshi.com/tsunami-simulation/ を開く（インストール・ログイン不要）
2. 「よく使う地点」から、名古屋のプリセット（例：「ガーデンふ頭」「港区 東海通」）を1つ押す
3. 「海の高さ」の初期値（内閣府2025の市区町村別の海岸最大津波高）を確認し、必要ならスライダーで変える。名古屋港では潮位・防潮壁の既定値が入る
4. 「この地点で再現する」を押す（読み込みに十数秒〜数十秒）
5. ▶ で再生。速度（×1〜最速）と視点（俯瞰・地点・目線・衝突）を切り替えて見る
6. 「結果を見る」で、この再現と内閣府2025の想定（ケース01）を同じ物差しで比べる

- 条件をそろえて開く直リンク（例）：`https://share.akirafunakoshi.com/tsunami-simulation/?lat=35.0905&lon=136.8844&auto=1&n=768&h=5&tide=1.2&levee=1&crest=4.6&breach=1`（ガーデンふ頭・標準格子・海の高さ5m・満潮T.P.+1.2m・防潮壁4.6m・越流で破壊）
- 通信が制限された環境：`https://share.akirafunakoshi.com/tsunami-simulation/?demo=1`
