## 3. 問題の一覧（重要度の順）

重要度の目安：**致命**＝誤った結果を正しい値のように見せる／**重大**＝審査員の第一印象や PLATEAU の評価を直接落とす／**中**＝気づかれると減点になりうる／**低**＝仕上げ

### #1【致命】標高タイルが一部だけ欠けると、その部分が海になり、警告なしで計算が始まる
- **再現手順**
  1. 船見町を選ぶ。`#go` を押した直後から、`dem5a_png` と `dem_png` のタイルを半分だけ（x＋y が偶数のもの）遮断する（`extra.mjs`）
  2. 計算が普通に始まり、陸の中に四角い「海」ができて水が入る（`N_partial_dem_after.png`）
  3. `#go` を押した直後に通信をすべて遮断すると、地点が標高 −14.0m（海面より低い）になり、「ここの深さ 15.88m／2階の床を超えています」と表示される（`N_offline_mid_after.png`）
- **原因**：`src/data/region.js` の59行目の周辺。エラーにするのは「全部のタイルが失敗したとき」（`d5.got + d10.got === 0`）だけで、5m と 10m の両方が欠けた格子は `water=1`（海・川）として扱われる。本来の海（404）と通信の失敗を区別していない。広域側（102行目）も同じ
- **推奨修正**：`loadDemMosaic` の `failed`（404以外）が1枚でもあれば、読み込みを止めて「一部の地形を取得できませんでした。再試行」と表示する。少なくとも、失敗したタイルの範囲は海にしない（10m に落とす／もう一度取りに行く）。計算画面にも「データの欠け」を表示する

### #2【重大】既定の「俯瞰」視点で、主役の「ここ」の柱が操作パネルの裏に隠れる
- **再現手順**：1440×900 で「港区 辰巳町」を選び、再現を開始する。`ここ` のラベルは y=784 にあり、dock（y=722〜884）の下に入る。1920×1080 の善進本町でも y=943（dock は 902〜1064）、390幅の辰巳町でも y=634（dock は 580〜836）
- **スクリーンショット**：`P_pin_1440_ui.png` と、UI を消した `P_pin_1440_noui.png`。ほかに `P_pin_1920_*.png`、`P_pin_390_*.png`、`p01_sim22s.png`、`p02_sim22s.png`、`T_depth_off_both.png`（凡例が出ると dock が高くなり、さらに隠れる）
- **原因**：`views.over()` が、注視点を「地点から海へ35%」の位置に置き、カメラを地点の後ろに下げている。そのため地点が画面の下端に寄り、HUD と dock の大きさを考えていない
- **推奨修正**：注視点を地点寄りにする。またはカメラのビューオフセット（`camera.setViewOffset`）や、dock の高さ分だけ画面の中心を上にずらした構図にする。初期表示のときに、地点が「HUD と dock を除いた領域」に入っているかを自動テストで確認する

### #3【重大】描画の解像度を自動で下げたあと、元に戻らない
- **再現手順**：1440×900 でガーデンふ頭を開始し、`#stage3d canvas` の width を5秒ごとに読む。開始直後の1秒間に 47fps になると 1224×765 に下がり、そのあと55秒間 60fps が続いても**戻らない**（`extra.log`、`S_resolution_after60s.png`）。レイアウトの計測では、1920×1080 が 1002×563、768×1024 が 400×534 まで下がっていた
- **原因**：`src/main.js` の fps による調整（HEAD 578〜579行目、作業コピー 799〜800行目）が `fps > 70` のときだけ解像度を上げる。60Hz の画面では requestAnimationFrame が 60fps を超えないので、上げる条件を満たさない。下げる条件（`fps < 40`）は、読込直後のシェーダー準備や、内陸地点で詳しい計算が始まる瞬間に一時的に満たされる
- **推奨修正**：上げる条件を「55fps 以上が3秒続いたら」のように変える。開始から2〜3秒は測らない。`prScale` を地点ごとに 1 に戻す（今はモジュール全体で1つの値を共有しているため、前の地点で下がった値を次の地点に持ち越す）

### #4【重大】PLATEAU の建物が非公式のミラーに頼っている。取れなくても何も表示されず、出典は PLATEAU のまま
- **再現手順**：`shiworks.xsrv.jp` を遮断してガーデンふ頭を開始すると、普通に始まり（`N_plateau_after.png`）、国土地理院の建物（高さは推定値）に切り替わる。画面には何も出ない。`experimental_bvmap` も同時に遮断すると建物が0棟になるが、それでも警告は出ず、防潮壁も消える（上部の表示から「防潮壁4.6m」が消える。`N_plateau_bvmap_after.png`）。どちらの場合も、画面下の出典には「PLATEAU（国土交通省）」と表示されたまま
- **原因**：`src/data/tiles.js` の `URLS.plateau`（有志が変換・配信している PMTiles）と、214行目の `catch { /* PLATEAU mirror unreachable → bvmap */ }`
- **推奨修正**：A1 が作っている公式データの静的配信（`public/plateau/`）を優先して、自分のサーバーから配る（A2 が統合中の作業コピーでは、`region.js` に `res.plateau` が追加されている）。建物の出どころ（PLATEAU／地理院の推定／なし）を HUD か結果画面に必ず表示し、PLATEAU が取れなかったときは出典の表示も切り替える。建物が0棟のときは警告を出す

### #5【重大】「この地点で再現する」ボタンとエラー表示が、スクロールしないと見えない
- **再現手順**：1920×1080 でも `#go` は y=1225 にあり、カードの表示範囲（1046px）の外になる（`L_w1920_2selected.png`、`L_w1440_2selected.png`）。390幅では y=1591 で、カードの表示範囲は488px。プリセットを押してもカードは自動でスクロールしない（`L_w390_2selected.png`）。国土地理院を遮断すると「地形データを取得できませんでした」の警告が出るが、これもスクロールの下にあって画面では見えない（`N_gsi_all_pick.png`）
- **推奨修正**：地点が決まったら、`#sel` を `scrollIntoView` で表示する。または `#go` をカードの下端に固定する（sticky）。警告はボタンのすぐ上に出す。モバイルでは、地点を選んだらプリセットの一覧を畳む

### #6【重大】WebGPU が使えない環境では、作品の中身がまったく見られない
- **再現手順**：`navigator.gpu` を無効にして開くと、「この端末では再現を表示できません」の文面と、ハザードマップへのリンクだけが表示される（`G_nogpu_1440.png`、`G_nogpu_390.png`）。`requestAdapter()` が null を返す場合も同じ画面になる
- **影響**：古い Safari、Linux の Chrome、会社の管理 PC（GPU が無効になっている）などで開いた審査員には、作品名も画面の例も伝わらない
- **推奨修正**：この画面に、作品名、デモ動画（A7 の素材）かスクリーンショット3枚、推奨環境（6章）を載せる。ページの最初の画面にも「推奨：PC の Chrome／Edge 最新版」と小さく表示しておく

### #7【中】地点を選ぶカードの標高と、計算画面の標高の値が大きく違う
- **例**：ガーデンふ頭は、カードでは「地盤の標高 約0.8m」、HUD では「地面の標高 3.7m」。種崎は 4.5m と 5.6m、尾鷲は 4.4m と 2.8m（`p05_pick.png` と `p05_sim22s.png`）
- **原因**：カードは地点を決めるときの10m DEM を読み、HUD は 5m DEM の、しかも建物を避けて動かした柱の位置を読んでいる
- **推奨修正**：カードの値は「目安」だと強調するか、読込のあとで HUD と同じ値に置き換える。とくに「海抜ゼロメートル地帯です」の判定（0.5m 未満）が、この目安の値で決まっている点に注意

### #8【中】住所検索とプリセット名のずれ
- 「名古屋駅」で検索すると、候補の先頭が「千葉県成田市名古屋」、次が「新潟県佐渡市名古屋」になる（国土地理院の住所検索 API の並び順。`R_4_search.png`）。先頭を選ぶと「周囲16km以内に開けた海が見つかりませんでした」になる
- プリセット「徳島市 沖洲」の座標（34.0550, 134.5531）は、実際には**徳島市 沖浜一丁目**（阿波富田駅の近く）で、沖洲ではない（`p13_pick.png`）
- **推奨修正**：検索の候補は、選んでいる地図の範囲に近いものや、都道府県の一致するものを上に並べる。駅名などのランドマークは、よく使うものを辞書として持つ。プリセットは名前か座標のどちらかを直す

### #9【中】内陸地点（名古屋駅など）は、しばらく見ても変化が分からない
- 名古屋駅では、開始から22秒後（約22分後）に水の先端が 7.9km 先で、画面は街の空撮のまま（`c01_nagoya_sta_sim22s.png`）。約84分後まで進めても、地点の周りの詳しい計算は「待機中」のまま
- 内陸では上部の表示に「防潮壁4.6m」が出ない（詳しい計算の範囲に防潮壁のセルが無いため）。実際には広域の計算で防潮壁を使っている
- 「広域」の視点では、「ここ」の柱が見分けにくい
- **推奨修正**：内陸地点では最初に「この地点には届かない可能性があります。広域の水の広がりを見てください」と伝え、深さで色分けを最初からオンにする。上部の表示には、広域の防潮壁も反映する。審査員向けのプリセットには、水が届く地点（富田町の周辺など）を1つ入れておく

### #10【中】結果画面（モーダル）をキーボードで扱いにくい
- `role="dialog" aria-modal="true"` を指定しているが、開いてもフォーカスが中へ移らない（`document.activeElement` は BODY のまま）。**Esc で閉じない**。フォーカスが外へ出ないようにする処理（フォーカストラップ）も無い
- **推奨修正**：開いたら `#r-close` か見出しへフォーカスを移し、Esc で閉じ、閉じたら「結果を見る」ボタンへフォーカスを戻す。`<dialog>` 要素の `showModal()` を使えば、まとめて解決できる

### #11【中】選び直したあと、早送りボタンの表示と実際の速さが合わない
- **再現手順**：内陸地点か1段の地点で「最速」を押す →「地点を選び直す」→ 別の沿岸の地点を開始する。ボタンは「最速」が選ばれたままなのに、実効は ×21（`V_funami_impact.png`、`T_depth_off_both.png`）
- **原因**：`createApp` で `st.speed = 20` に戻しているが、`#speeds` の `on` クラスを戻すのは内陸地点（`far`）のときだけ
- **推奨修正**：地点ごとに、`st.speed` に合わせて `on` クラスを必ず付け直す

### #12【中】「衝突」視点で、カメラが建物に張り付くことがある
- 船見町の「衝突」は、画面いっぱいに建物の壁が映り、水も地点も見えない（`V_funami_impact.png`）
- **推奨修正**：`views.impact()` で、カメラの位置が建物の中にないか、カメラと注視点のあいだに建物がないかを確かめる（`eye` と同じような判定）。だめなら方角を変える

### #13【中】内陸地点では、×1 と ×5 が効かない
- 名古屋駅で ×1 と ×5 を押すと、どちらも実効 ×8（3秒で時計が約25秒進む）
- **原因**：広域の計算は、1フレームに最低1回は計算を進める（`Math.max(1, …)`）。約14m 格子の dt が大きいため、60fps で約 ×8 になる
- **推奨修正**：広域の計算も、時間の貯金方式（1フレームで dt に満たないときは計算を進めない）にする。または、内陸地点では ×1／×5 を無効にする

### #14【中】選び直すたびに JS ヒープが増える（リークの疑い、要確認）
- 8回の選び直しで 869MB から 1559MB になった（GC の前後の区別はしていない）。スマートフォンやメモリの少ない PC では、選び直しを続けると落ちる可能性がある
- **推奨修正**：dev サーバーの `__t` で、選び直しを10回したあとに `gc()` を実行してヒープを測る（Chrome の `--js-flags=--expose-gc`）。`dispose()` で、読み込んだ ImageBitmap や OffscreenCanvas、地図の GeoJSON レイヤーが解放されているか確認する

### #15【中】出典の表示がモバイルで消える・隠れる
- 390幅では、計算画面の `.credit` が `display:none` になっている（国土地理院・PLATEAU・内閣府の出典が見えない）。地点を選ぶ画面では、地理院タイルの出典バッジがカードのプリセット（串本町など）に重なる（`L_w390_2selected.png`）
- **影響**：国土地理院のコンテンツ利用規約で求められる出典の表示と、PLATEAU の出典の明記が、モバイルでは満たされていない。応募作品として指摘されやすい
- **推奨修正**：モバイルでは、出典を「i」ボタンで開く形にするか、dock の中に1行で入れる。MapLibre の出典コントロールは、カードと重ならない位置（右上など）へ移す

### #16【低】表示の細かい崩れ
- 名古屋駅の「目線」で、「2階の床 3m」と「海の高さ 5.0m ＝ 地面から 2.9m」のラベルが重なる（`V_nagoya_eye.png`）
- HUD の「−0.2m（海面より低い）」が2行に折り返す（`p01_sim.png`）
- 画面下の出典と dock が3px重なる（1280〜1920 の全幅）。768幅では `#perf` と dock が重なる
- 768×1024（タブレット）は、760px を超えるためデスクトップ用の配置になり、地点を選ぶカードが地図の半分以上を覆う（`L_w768_2selected.png`）
- 1440×900 などでは、プリセットを押した直後に計算範囲の四角が地図に出ないことがある（徳島や390幅では表示される。タイミングの問題の可能性があり、要確認）

### #17【低】コンソールに 404 のエラーが毎回出る
- 国土地理院は、海の部分のタイルに 404 を返す。これがブラウザのコンソールに「Failed to load resource: 404」として、1地点あたり0〜8件出る（アプリの動きとしては正常）
- **影響**：DevTools を開いた技術寄りの審査員に「エラーが出ている」と見られる可能性がある
- **推奨修正**：README か「このサイトについて」に「海域のタイルは 404 が正常」と書いておく。可能なら、事前に分かる海域のタイルは取りに行かない

### #18【低】結果画面の背景が透けて読みにくい（モバイル）
- 390幅では、結果画面のカードを通して、下の HUD の数字（0.00m など）が透けて読める（`L_w390_7result.png`）
- **推奨修正**：結果画面のカードの背景を、不透明に近い `--panel-solid` にする

### #19【低】読み込みに失敗したときの案内が、開発者向けになっている

- **推奨修正**：「もう一度試す」ボタンと、「合成の港町で試す」ボタンを置く

### #20【低】そのほか

## 6. 審査員向けの注意（推奨環境の案）

応募フォームやスライドの「動作環境」の欄（A3・A4 担当）に、次の内容を入れることを提案する。

- **推奨**：PC（Windows／macOS）の Chrome または Edge の最新版。画面は 1280×800 以上。**今回の確認はこの条件（Apple Silicon の Mac と Chrome 154）で行った**
- **動く可能性はあるが、今回は確認していない**：macOS／iPadOS／iOS 26 以降の Safari（アプリの非対応画面の案内では「Safari 26 以降」）、Android の Chrome、Windows の Firefox。Linux の Chrome は、WebGPU が既定で無効になっていることがある。いずれも実機での確認が必要（A3 に引き継ぎ）
- **動かない**：WebGPU が使えないブラウザ、GPU を無効にしている管理 PC、仮想デスクトップ（VDI）。この場合は非対応の画面になり、作品の中身は見られない（#6）。**審査員用にデモ動画のURLを必ず併記する**
- **通信**：国土地理院のタイルと、PLATEAU の PMTiles（現在は有志のミラー）を、その場で読み込む。社内のプロキシなどでこれらが遮断されると、読み込めないか、建物のない表示になる（#4）
- **最初に試す地点のおすすめ**：ガーデンふ頭（読込 約2秒、地点が画面に見える、公式想定 1.3m と比べられる）。名古屋のゼロメートル地帯のプリセットは、読込に 8〜14秒かかり、地点が操作パネルに隠れる（#2）ので、直るまでは2番目以降に案内する
- **時間の目安**：沿岸の地点は ×20 で約2分、最速なら約30秒で結果が出る。内陸地点（名古屋駅など）は ×60 で約90秒かかり、地点まで水が届かないことがある
