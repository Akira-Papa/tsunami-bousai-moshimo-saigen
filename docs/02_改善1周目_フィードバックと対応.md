# 改善1周目：フィードバックと対応（2026-09-24）

対象：名古屋港（名古屋市港区 港町）・海の高さ5m・格子768²（約2m）
証拠：修正前は `docs/review1/`、修正後は `docs/review2/` のスクリーンショット

## 実装前に検証で見つかった重大問題（ひかり）

| 症状 | 原因 | 対応 |
|---|---|---|
| 入力15mの津波で、海岸が30m・陸が42mまで積み上がった（高知） | 沖の造波で岸向きの流速を与え続けたため、保持中も運動量が注入され続けた | 水位のみの緩和に変更し、のちにリーマン不変量方式へ（汐見 #1） |
| 名古屋港の角で水位が20m超まで積み上がった | 陸側の外縁を「隣の値をコピー」にしていたため、流入方向の流れで外から水が無限に入った | 外縁のゴーストセルは流出のみ許可 |
| ダム崩壊の前線が理論の半分の速さ | 薄層の流速上限 2√(gh) が前線を止めていた | 上限を撤去し、脱特異化のεを1cm→1mmへ |
| 名古屋の中川区・南区・熱田区で津波高が空欄 | 内閣府2025の表に名古屋市は港区しか載っていない | 同じ市で最も高い区（港区5m）を代用し、画面に「代用値」と明示 |
| 内陸寄りの地点が選べない | 計算範囲が最大2.6km | 最大4kmへ拡大し、格子を比例して増やす（上限1280²） |

## 4人のフィードバックと対応

### 汐見 凪（物理）
| # | 指摘 | 対応 |
|---|---|---|
| 1 | 水位だけの注入では流入量が不足する | 造波をリーマン不変量方式に：内向き R⁺ は目標の長波、外向き R⁻ は水自身の値を使うので、反射波は自由に抜ける |
| 2 | 合成水深が浅すぎる（港内で1〜5m） | d = 3 + s/8（上限14m）。海岸距離をぼかして、45°の段々の等深線を消した |
| 3 | 2mセルの値を公式の「100m四方の最大」と比べるのは物差しが違う | 結果画面に「周辺100m四方の最大」を追加（公式と同じ物差し） |
| 4 | 保持時間が短い／潮位 | 保持を600→900秒へ。潮位は一次情報で確認できないため見送り（次の改善候補） |
| 5 | 海岸水位の制御が岸壁の反射ピークに引きずられる | 岸近くの帯の平均と最大の中間を制御量に。上げはゆっくり、下げは速く |
| 6 | 2次元のCFLが正値条件を超えうる | dt = 0.3dx/(15+c) |

### セーブル・オコンクォ（見た目）
| # | 指摘 | 対応 |
|---|---|---|
| 1 | カリブ海のような水色の海 | 伊勢湾らしい緑灰色の吸収・散乱。深い海底は見えないようにした |
| 2 | 建物の壁が裏返しで、中身のない箱に見える | 三角形の巻き順を修正し、外向きを表にした |
| 3 | 陸の水がペンキに見え、建物の影が落ちない | 高さ場を太陽方向へ14歩たどる影を水面に追加。細かい法線を流れ方向に4倍に伸ばした |
| 4 | 水際が2mセルの階段になる | ピクセル単位の水深 p.y − 地盤 で透明度を決める |
| 5 | 押し波の前面が見えない | 斜面×フルード数で泡を出し、ボア前面に透過光。遠景の細かい揺らぎは弱める |
| 6 | コースティクスが見えない | 周波数を1テクセルで表せる帯域へ。近景はworley 2層の光の網をピクセル単位で重ねる |
| 7 | 泡が白飛びしたペンキ | 泡の反射率を下げ、濁りで茶色へ。網目を残した。飛沫の不透明度は0.4倍 |

### 九条 刃（GPU）
| # | 指摘 | 対応 |
|---|---|---|
| 1 | 地点を選び直すたびに約300MB残り、数回でデバイスが落ちる | ソルバー・コースティクス・影・パスを dispose |
| 2 | ReadbackBufferのrelease漏れでHUDが止まる | finallyで必ずrelease |
| 3 | 読み込みの二重起動 | 世代番号で、古い読み込みは破棄する |
| 4 | コースティクスが一番重い | 光子格子の上限を1024に、描画は2フレームに1回 |
| 5 | 静的な影マップを毎フレーム描き直している | autoUpdate=false にし、太陽を動かした時だけ更新 |
| 6 | 解像度の調整がない／タブが非表示の時 | fpsに応じた画素比の調整、visibilitychangeで停止・再開 |

### 日向 灯（わかりやすさ）
| # | 指摘 | 対応 |
|---|---|---|
| 1 | 「8分で来る」と誤読される（時刻の基準が混在） | 時計は「押し波の開始から」。結果に「公式は地震から。名古屋港には1時間以上かけて届く想定」 |
| 2 | 3Dの札がモーダルの上に出る | 札の層をz-index 1に閉じ込め、モーダル表示中は隠す |
| 3 | ピンの札が重なる | 近づいた時だけ目盛りを表示。目盛りは左、階は右、2.5mは線だけ |
| 4 | 海の高さと浸水深がつながらない | 柱に「海の高さ5.0m＝地面から1.3m」の青い帯。HUDに地面の標高と差を表示 |
| 5 | 濁流が地面と同じ色で見えない | 陸に水が上がったら「深さで色分け」を提案。公式想定は斜線＋輪郭で描く |
| 6 | 「安全」と読まれかねない | 「この地点にはまだ届いていません（周りでは浸水が進んでいます）」「水の先端まで約40m」「備えは高いほう（1.7m）で」 |
| 7 | 名古屋らしさがない | 地点を「海抜ゼロメートル地帯」と「名古屋港」の2群に。標高が0.5m未満なら「海面より○m低い」を大きく表示。細い防潮壁・高潮防波堤を含まないことを開始前に明示 |

## 検証（修正後）
- 単体テスト3本はすべて合格：
  - 静止湖：流速3e-5、質量誤差2.5e-9
  - ダム崩壊：中央水深0.883（理論0.889）
  - 海浜の水位上げ：汀線3.15m（入力3m）
- 名古屋港：ここの最大1.07m。周辺100m四方の最大は1.74m（公式1.27m）。陸の浸水は0.91km²
