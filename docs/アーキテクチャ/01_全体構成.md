# 01 全体構成

「津波防災もしも再現」を、ソースコードから読み解いた構成図です。細かい根拠（`ファイル:行`）は 02〜06 の各章にあります。

図はすべて draw.io 形式の元ファイル（`図/*.drawio`）と、2倍解像度の PNG（`図/*.png`）で置いています。draw.io（デスクトップ版・VS Code 拡張・diagrams.net）で `.drawio` を開けば、そのまま編集できます。

---

## 1. ひとことで言うと

**サーバー処理のない、ブラウザだけで完結するアプリです。**

1. 地点を選ぶ
2. ブラウザが国土地理院などから標高・航空写真・建物を直接取得する
3. 取得したデータを格子にする
4. GPU（WebGPU の compute）で浅水方程式を解く
5. 同じ GPU 上のバッファとテクスチャから、そのまま水面を描く

配信するのは、Vite でビルドした静的ファイルだけです。置き場所は S3＋CloudFront で、公開パスは `/tsunami-simulation/` です。

## 2. データの流れ

![データフロー](図/03_データフロー.png)

- **`planDomain`** は、地点の近く（4.2km、z14）で広い水面を探します。
  - 見つかれば、地点と海を含む1.5〜4km四方で1段計算にします。
  - 見つからなければ、16km（z12）まで範囲を広げて探し、二段ネスト計算にします。広域は最大20km四方です。
- **`buildRegion`** は、標高・水面・建物・防潮線を N×N 格子にします。
  - 標高の無効値は水面として扱います。
  - 領域の縁につながる水面が「海」です。海底は合成の水深にします（`3 + s/8`、最大14m）。
  - 建物は、セルの中心がポリゴンの中にあれば「壁」にします。
- **`createSolver`** は、格子を `f32 vec4` のストレージバッファに載せます。
  - 以降のデータは、CPU を経由せず GPU の中だけで回ります。
  - CPU に戻すのは、HUD 用の数十バイトだけです（非同期で読み戻し）。

## 3. 1フレームの処理

![1フレームの処理](図/02_1フレームの処理.png)

- 前半の赤は GPU 計算、後半の紫は描画です。
- 計算は1ステップあたり2回の dispatch（SSP-RK2 の2段）です。数十ステップ分を `renderer.compute([...])` にまとめて投げます。
- 付随場（泡・濁り・濡れ・最大値）と `pack` は1フレームに1回です。
  - `pack` は描画用のバッファ `R`／`R2` と、テクスチャ `surfTex`／`envTex` を書きます。
- コースティクスは2フレームに1回、影マップは最初の1回だけ描きます（太陽は固定）。

## 4. 内陸の地点（二段ネスト計算）

![二段ネスト計算](図/05_二段ネスト計算.png)

名古屋駅のように海から遠い地点では、計算を2段に分けます。

- **広域（外側）**：約14mの格子で、海から街への広がりを計算します。建物は壁ではなく、粗度で表します。
- **詳細（内側）**：約2mの格子で、地点の周りを計算します。建物は反射壁です。
  - 縁から70mの帯で、外側の解に緩和します。
  - 水の先端が遠いうちは、内側は時計だけを進めて計算を省きます。

## 5. テクスチャはどうしているか（要点）

![テクスチャとGPUリソース](図/04_テクスチャとGPUリソース.png)

テクスチャは、次の3種類に分かれます。

1. 読み込み時に CPU で1回だけ作るもの
2. GPU の compute が毎フレーム書き換えるもの
3. 描画パスが作るもの

加えて、テクスチャを経由せず、ストレージバッファを頂点シェーダーが直接読む経路があります。

| 種類 | 名前 | 中身 | 使い道 |
|---|---|---|---|
| CPU・1回 | `photoTex` | 地理院の航空写真（z16〜17）を 3072〜4096px の Canvas に貼り合わせたもの。sRGB、ミップマップあり、異方性8 | 地面の色、建物の屋根、水の中から見える水底（屈折先） |
| CPU・1回 | `bedTex`（N×N、RGBA 半精度） | R＝地盤・海底、G＝建物の高さ、B＝海フラグ、A＝**日が当たる最低水位** | 水面シェーダーが水深・影・映り込み・海底色に使う |
| CPU・1回 | `offTex`（2048²） | 公式想定の100mセルを、深さの色の斜線と輪郭で描いた Canvas | 地形に重ねる「公式想定」の表示（トグルで切り替え） |
| GPU・毎フレーム | `surfTex`（StorageTexture、半精度） | R＝描画用の水深、G・B＝水面の法線、A＝濁り | コースティクスの光子格子が、屈折の計算に読む |
| GPU・毎フレーム | `envTex`（StorageTexture、半精度） | R＝濡れ、G＝最大水深、B＝泡、A＝最高水位−地盤 | 濡れた地面が暗くつやを持つ、泥の膜、建物の泥の線 |
| 描画パス | `causticRT`（≤2048²、半精度） | 光子格子を加算合成した光の集中度（面積比） | 水底のコースティクス |
| 描画パス | 影マップ（2048²／4096²） | 太陽が固定なので `autoUpdate=false`。1回だけ描く | 地形・建物・防潮壁の影 |
| バッファ直読み | `R`／`R2`（vec4 f32） | (水位, 法線 x・z, 水深)／(泡, 濁り, u, v) | 水面メッシュの頂点1つ＝計算セル1つ。`vertexIndex` で直接読む |

ポイントは3つです。

- **水面にテクスチャを使わない。**
  - 水面の頂点シェーダーは、ソルバーの出力バッファ `R`／`R2` を `vertexIndex` で直接読みます。
  - 計算結果を CPU に戻さず、テクスチャへのコピーもしないので、毎フレームのコストがほとんどかかりません。
- **影はレイトレースせず、焼き込む。**
  - 読み込み時に、各セルから太陽側へ最大64セル歩きます。そして「この水位より上なら日が当たる」高さを `bedTex.A` に焼き込みます。
  - 水面シェーダーは、その値と比べるだけで、建物の影に入った水を暗くできます。
- **コースティクスは面積比法で描く。**
  - `surfTex` の法線で、光子格子の各点を水底まで屈折させます。
  - 変形後の三角形が小さくなるほど明るくします（元の面積÷変形後の面積）。
  - 結果を `causticRT` に加算し、水面シェーダーで水底の色に掛けます。
  - 近景には、手続き的な光の網（worley）を足します。

全テクスチャの解像度・形式・フィルタ・チャンネルの意味・書き手と読み手は、[04 描画とテクスチャ](04_描画とテクスチャ.md) の 1.1 の表にまとめています。
