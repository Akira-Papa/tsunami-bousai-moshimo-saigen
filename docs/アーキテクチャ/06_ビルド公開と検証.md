## 2. Vite 設定（`vite.config.js`）

```js
export default {
  base: './',
  plugins: [shotSaver],
  build: { target: 'esnext' },
  worker: { format: 'es' },
  esbuild: { target: 'esnext' },
  optimizeDeps: { exclude: ['maplibre-gl'], esbuildOptions: { target: 'esnext' } },

```

（`vite.config.js:23-33` を要約したもの）

### 2.1 `base: './'`：どのサブフォルダでも動くようにする

- 設定は `vite.config.js:24` です。コメントは「works from any sub-folder」です。
- ビルド後の `dist/index.html` は、スクリプトとCSSを相対パスで読みます（`./assets/index-*.js`、`./assets/index-*.css`）。
- 実行時に読むデータのURLも、`import.meta.env.BASE_URL` から組み立てています（`base: './'` のときの値は `./`）。
  - `src/data/plan.js:6`、`:8-9`：`data/tsunami_h.json`、`data/municipalities.json`
  - `src/data/official.js:5`、`:7`、`:23`：`inundation/manifest.json`、`inundation/…`
- このため、ドメイン直下ではなく `/tsunami-simulation/` の下に置いてもリンクが切れません。

### 2.2 `build.target` / `esbuild.target` / `optimizeDeps.esbuildOptions.target` を `esnext` にする

- 設定は `vite.config.js:27`、`:31`、`:32` です。
- `src/main.js:24` では、モジュールの最上位で `await navigator.gpu.requestAdapter()` を実行しています。
- 最上位の `await` を古い構文へ下げずに、そのまま出力する設定です。

### 2.3 MapLibre を `optimizeDeps` から外し、Worker を `?worker&url` で同梱する

**事実（コードで確認したこと）**

1. `src/picker.js:4-7` は、MapLibre の Worker を明示的に同梱して登録しています。
   ```js
   import maplibreWorkerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url';
   maplibregl.setWorkerUrl(maplibreWorkerUrl);
   ```
   コメントには、この設定がないと公開ビルドで次のようになると書かれています。
   - 「Worker failed to load」が出る
   - 地図に計算範囲（GeoJSON）の輪郭が出ない
2. MapLibre 6.11.1 は、既定では Worker の場所を自分のファイルからの相対位置で探します（`node_modules/maplibre-gl/dist/maplibre-gl.mjs`）。
   - `new URL('./maplibre-gl-worker.mjs', import.meta.url)` の形です。
   - Worker は `new Worker(url, { type: 'module' })` で起動します。モジュールWorkerが使えないときは、クラシックWorkerに切り替えます。
3. ビルドすると、Worker は別ファイル `dist/assets/maplibre-gl-worker-*.js` として出力されます。本体の `dist/assets/index-*.js` には、そのファイル名が文字列として埋め込まれます（`grep` で確認）。

**コードから読み取れる理由（`vite.config.js` にコメントはない）**

- ビルド後は MapLibre が本体の JS に取り込まれます。そのため `import.meta.url` の隣に `maplibre-gl-worker.mjs` はなく、既定の探し方では読み込みに失敗します。
  - `?worker&url` で Worker を別の資産として出力し、ハッシュ付きの正しいURLを `setWorkerUrl` に渡すことで、これを避けています。
- `worker: { format: 'es' }`（`vite.config.js:30`）は、同梱する Worker を ES モジュールとして出力する設定です。
  - MapLibre は Worker を `type: 'module'` で起動するので、それに合わせた形式です。
  - `maplibre-gl-worker.mjs` 自体も ES モジュールです。
- `optimizeDeps.exclude: ['maplibre-gl']`（`vite.config.js:32`）の理由はコメントがありません。
  - 開発サーバーの事前バンドルから MapLibre を外すと、`node_modules/maplibre-gl/dist/` の配置のまま配信されます。
  - その結果、`maplibre-gl.mjs` と `maplibre-gl-worker.mjs` が同じ場所に並び、Worker の相対解決が崩れない、という効果があります。
  - これが設定した意図かどうかは未確認です。

### 2.4 開発時の `/__shot` 保存プラグイン

- 定義は `vite.config.js:4-21`、登録は `:25` です。
- `POST /__shot?name=xxx` で受け取った PNG を、`./shots/xxx.png` に保存します。
  - 名前は `[^\w-]` を取り除いて整えます（`:7`）。
  - POST 以外は 405 を返します（`:6`）。
- 登録先は `configureServer` と `configurePreviewServer` の2つです（`:19-20`）。
  - つまり `npm run dev` と `npm run preview` でだけ動きます。
  - S3 などの静的配信には存在しません。
- 呼び出し元は、開発時だけ定義される `window.__t.shot(name)` です（`src/main.js:652-669`、`:666` で `fetch('/__shot?...')`）。
- `shots/` は `.gitignore:3` でリポジトリから外しています。

## 4. 公開手順

公開先は `https://share.akirafunakoshi.com/tsunami-simulation/` です（`package.json:8`、`README.md:9`）。

配信の構成は次のとおりです。

- 共有サイトのリポジトリ `~/workspace/share.akirafunakoshi.com/` の中に `tsunami-simulation/` フォルダがあります。
  - 現在の中身は `assets/`、`data/`、`index.html`、`inundation/` で、`dist/` と同じ構成です。
- そのフォルダを S3 に同期し、CloudFront から配信します。

### 4.1 手順

```bash
# 1) ビルド
cd ~/workspace/検証用/tsunami-city-webgpu
npm run build

# 2) 公開用フォルダへ配置（古いハッシュ付きファイルを残さないよう、中身を入れ替える）
rsync -a --delete dist/ ~/workspace/share.akirafunakoshi.com/tsunami-simulation/

# 3) そのフォルダだけを S3 へ同期（--delete は必ずこのフォルダに限定する）
cd ~/workspace/share.akirafunakoshi.com
aws s3 sync ./tsunami-simulation/ s3://share.akirafunakoshi.com/tsunami-simulation/ --delete

# 4) CloudFront のキャッシュを、このパスだけ無効化する
aws cloudfront create-invalidation \
  --distribution-id <DISTRIBUTION_ID> \
  --paths "/tsunami-simulation/*"
```

- 認証情報、AWS のプロファイル名、アカウントID、CloudFront のディストリビューションIDは、このドキュメントには書きません。`<DISTRIBUTION_ID>` は各自の環境の値に置き換えてください。
- **`--delete` をフォルダの外に使わないこと。**
  - 共有サイトのリポジトリにある `npm run s3upload:dev` は、`aws s3 sync . s3://share.akirafunakoshi.com/` でサイト全体を同期するスクリプトです（`share.akirafunakoshi.com/package.json:6`、`--delete` なし）。
  - ここに `--delete` を付けたり、同期元をリポジトリ全体にしたりすると、ほかの公開ページまで巻き込みます。
  - 必ず `tsunami-simulation/` の中だけを同期してください。
- `index.html` はハッシュの付かない固定の名前です。無効化しないと、古い `index.html` が新しいビルドでは消えた `assets/index-<旧hash>.js` を指したままになることがあります。

### 4.2 HTTPS が必須な理由（WebGPU はセキュアコンテキスト限定）

- アプリは起動するとすぐ `navigator.gpu.requestAdapter()` を呼びます。失敗したときは「この端末では再現を表示できません」の画面（`#nogpu`）に切り替えて止まります。
  - 判定は `src/main.js:23-25`、画面は `index.html:185-191` です。
- WebGPU の `navigator.gpu` は、セキュアコンテキストでしか公開されません。
  - HTTPS のページ、または `localhost` / `127.0.0.1` のことです。
  - HTTP で公開すると、WebGPU に対応したブラウザでも `navigator.gpu` が `undefined` になり、必ず非対応の画面になります。
- 開発サーバーを `127.0.0.1` で待ち受けている（`package.json:11`）ので、開発中は HTTP でも動きます。公開では CloudFront の HTTPS で配信する必要があります。
- 対応ブラウザ：Chrome / Edge 113 以降、Safari 26 以降（`README.md:17`、`index.html:188`）。

### 5.2 ヘッドレス Chrome による数値の検証とスクリーンショット

これまでの記録では、ヘッドレス Chrome で実際の画面を開いて、数値と見た目を確かめています（`docs/04_満潮位と防潮壁の追加.md:81`、`docs/05_内陸地点のネスト計算.md:19`）。

- 道具は `puppeteer-core` と、インストール済みの Chrome の組み合わせです。
  - どちらもこのリポジトリの依存には入っていません（1.3節）。
- 起動するときに `--enable-unsafe-webgpu` を付け、ヘッドレスでも WebGPU を有効にします。
- 開くURLは、自動開始のディープリンクを使います（`README.md:19`、`src/main.js:628-646`）。
  - 例：`?lat=35.0905&lon=136.8844&auto=1&n=768&h=5&tide=1.2&levee=1&crest=4.6&breach=1`
  - 地点の計画（`sel.plan.ok`）ができるまで300ms ごとに確かめ、準備ができたら条件を反映して「この地点で再現する」を押します（`src/main.js:632-644`）。
  - `?demo=1` を付けると、通信なしの合成の港町で動きます（`README.md:18`、`src/main.js:628`）。

最小の例です（あくまで例で、リポジトリに同じスクリプトはありません）。

### 5.4 検証するときの注意

- **ページが非表示だと、計算と描画が止まります。**
  - `visibilitychange` で `document.hidden` のとき `renderer.setAnimationLoop(null)` を実行し、表示に戻ったら再開します（`src/main.js:621-625`）。
  - アプリ内ブラウザのペインを隠している間やタブが裏にある間は、時計もGPUの計算も進みません。
  - 数値を取るときは、ページを表示したままにするか、`__t.advance()` で時間を明示的に進めてください。
- **サイズ0のビューポートは無視されます。**
  - `onResize` は `innerWidth` / `innerHeight` が0のとき何もしません（`src/main.js:613-619`）。
  - 自動検証ではビューポートを明示的に指定してください。
- **地点を選び直す検証も入れます。**
  - 2回目以降の地点で真っ黒になる不具合（6章）があったので、3回続けて切り替え、GPUエラーが0件であることを確かめています（`docs/04_満潮位と防潮壁の追加.md:81`、`docs/05_内陸地点のネスト計算.md:26`）。
- **ネット越しに取るデータに左右されます。**
  - 地理院・PLATEAU のタイルは実行時に取得します（`src/data/tiles.js:12-13`）。
  - 通信に左右されない確認には `?demo=1` を使います。
