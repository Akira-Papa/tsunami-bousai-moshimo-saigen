## 中

### 中1　タブレット幅（768×1024）と横長（1024×768）で、HUD とドックが重なる（修正前より悪化）
- 場所：`src/main.js:22`（`isSmall = Math.min(innerWidth, innerHeight) < 700`）、`:183-189`（HUD と「表示の切りかえ」を非 small で開いたままにする）、`src/style.css:199-201`（761〜1100px の帯）

- 実測（getBoundingClientRect）：
  - 1024×768：HUD が 上64〜下838（画面の高さ768を70px超過）。HUD×ドック 214×204px、HUD×「結果と、このあとすること」ボタン 179×40、HUD×出典帯 280×45。HUD の下半分（「近くの建物」の一覧と「入れるか分かりません」の注意）がドックの下に隠れて読めない。
  - 768×1024：HUD×ドック 280×77、HUD×視点ボタン 134×17、HUD×時計 263×32。
  - 修正前（同じ操作、c2ec6d5）：1024×768 は HUD×ドック 214×115（HUD は画面内）、768×1024 は HUD×ドックの重なりなし。つまり新しく足した「近くの建物」欄で HUD が縦に伸び、重なりが増えた。PC 1440×900 は HUD×ドック 6px だけ（問題なし）。
- 問題：P0-5 で足した「入れるか・上がれるかは分かりません。市町村の情報で確かめてください」の注意が、この2つの幅では HUD の画面外または裏に入る。
- 直し方：`isSmall` を「幅 1100px 以下、または高さ 800px 以下」に広げ、HUD は「くわしく」を閉じた状態から始める。または `.hud` に `max-height: calc(100dvh - dock高 - 上端) ; overflow-y: auto` を付ける。

## 軽微

1. **スマホで「この地点で、3Dで再現する」まで約3画面分スクロール**。選んだ直後、ボタンは シート内 約1560px 下（`go-bar` は `position: sticky` だが `.sim-setup` の中だけで効くため、そこへ着くまで見えない。`style.css:239`、`main.js:58`）。着いたあとは下端に張り付き、隠れない（390×844：実際のタップが `#go` に当たる、48px 高）。1024×768 では、地図の出典帯が `go` の下端 14px を覆う（`shots_C/land_2b_go_scrolled.png`）。直し方：選択直後に、公式想定の見出しの近くに「3Dで再現する」への小さなリンク（アンカー）を置く。
2. **結果ダイアログから「わが家の避難メモ」を開くと、結果ダイアログが閉じ、メモを閉じても結果に戻らない**（`src/ui.js:42-44` の `openDialog` が先に `closeDialog()`、`src/memo.js:64`）。閉じたあとのフォーカスは「結果と、このあとすること」ボタン。結果は読み直しになる。直し方：メモをダイアログの上に重ねる（結果を閉じない）か、閉じたあと結果を開き直す。
3. **フォーカスの行き先**：プリセットや検索結果で選ぶと、フォーカスは（画面外へスクロールされた）プリセットボタンか `body` に残る（検索結果は `body`）。次の Tab で公式想定の一覧まで、プリセットを約12回通る。「3Dで再現する」と「地点を選び直す」を押した後も `body`。直し方：地点選択後は、公式想定の見出し（`tabindex=-1`）へフォーカスを移す。
4. **`#brief-live` は1回だけ**：通信を切って地点を選ぶと「公式想定：取得できませんでした。逃げる場所：取得できませんでした」と読まれ、「もう一度」で成功しても読み上げが更新されない（`brief.js:150-154` の `cur.said`）。再試行の成功時に更新する。
5. **ランドマーク**：`<main>` がない。再現中の画面（`#sim`）に見出しがない。`#load` セクション全体が `aria-live="polite"`（進行の文が段階ごとに読まれる。過剰ではないが長い）。`#brief-live` `#h-say-live`（段階が上がるときだけ）`#r-share-msg` `#memo-saved` の使い方は適切。
6. **WebGPUなし**：理由の文（`#gpu-note`）がスマホ390×844の最初の画面の外（上端 966px。シートの高さ 521px）。説明の冒頭「公式想定の確認 ＋ 3Dの物理シミュレーション」「さらに…再現できます」が前に出る。3D専用の図（「海の高さ／ここの深さ」の `.terms`：PC幅で表示）と「防潮壁は…指定した高さで入れます」の注も、3Dを使えない端末で出る。`#gpu-note` を見出しのすぐ下へ。
7. **共有リンクで `h=8`** のとき、「初期値は内閣府…5m」と出るのにスライダーは 8.0（リンクの値を使っているという一言がない）。値そのものは正しく入り、別の地点を選ぶと既定に戻る（確認済み）。
8. **再現の開始が終わらなかった1回**（原因不明・再現せず）：`?lat=35.1709&lon=136.8815&n=512`（内陸、二段計算）で「3Dで再現する」を押したあと、400秒待っても `#sim` が出なかった。同じ条件の再実行は 2回とも2〜10秒で開始。その時間帯は他のレビュー役の GPU 作業が重なっていた可能性がある。開始待ちに上限と文言がない（`main.js:310-312` の `createApp` に タイムアウトなし。「地点選択に戻る」は常に押せる）。
9. **タップ領域 44px 未満**（スマホ390）：地点プリセット 34px 高、速度ボタン `×1` 37×40・`最速` 42×40 など、視点ボタン 42〜43×40、表示の切りかえのチェック 32px、`地点を選び直す` 36px、`くわしく` 36px、`結果と、このあとすること` 40px、トーストの「×」39×36。最重要の「3Dで再現する」(48px)・再生 ▶（約44px）は十分。MapLibre の拡大縮小は 29×29、出典の「i」は 24×24。
10. **キーボード**：Tab 順の先頭に地図とその操作（5か所）が来て、検索欄まで着かない（地図の下に検索がある順）。`:focus-visible` は全体に3pxの白い枠で、MapLibre の部品だけ枠なし（青い影に置き換わる）。

| 項目 | 結果 |
