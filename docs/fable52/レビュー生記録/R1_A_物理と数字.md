## 総評

## 中

### 中-1　公式の到達時間を「四捨五入」している（遅い側に寄る）
- 場所：src/brief.js:37、src/main.js:713・803、src/memo.js:`Math.round(o.cell.arrival / 60)`
- 問題：画面は「地震から**最も早くて**約N分」と言うが、`Math.round` なので 2分40秒 → 約3分、2分20秒 → 約2分となり、半分は「実際より遅く」見える。「最も早くて」は下限を意味する言葉なので、丸めは切り捨てでなければならない。また 30秒未満は「約0分」と出る（実データ：到達時間があるセル 374,680 個のうち 139 個が 30秒未満、28 個が 0 秒。600秒未満のセルの約半数 46,715/94,228 で round と floor が食い違う）。
- 直し方：`Math.floor(sec/60)` にする。1分未満は秒で「約N秒」または「1分未満」と出す。3箇所（brief／main の2箇所／memo）を共通関数にまとめるのがよい。
- 実データでの照合：ガーデンふ頭の100mセルは 6504 秒 = 108.4 分 → 「約108分」（切り捨てでも同じ）。高知市種崎のセル（0.24m）は 2430 秒 = 40.5 分 → 現行は「約41分」、切り捨てなら「約40分」。

### 中-2　「約Nm先から浸水の想定があります」の距離がセルの中心までで、実際より遠く言う
- 場所：src/data/official.js:64-72（officialAround の nearest）、src/brief.js:33、src/main.js:719
- 問題：`nearest` は100mセルの中心までの距離。セルは100m四方なので、一番近い縁はそこより最大約50〜70m近い。実測（高知市種崎 33.5061,133.5693）：最寄りセルの中心は83m（→画面は「約80m先」）だが、そのセルの縁は東へ17mの所にある。「先」と書くと、実際より遠く（安全側でなく危険側に）読める。
- 直し方：縁までの距離（中心距離 − 50m を下限0）で出す、または「約80m先の100mセルの中心」「すぐ隣の100m四方から」と書く。近い（縁まで50m未満）なら「すぐ隣の100m四方に浸水の想定があります」と言い切るのがよい。

### 中-3　結果画面の建物の表に、公式列・再現列とも単独の「浸水なし」が出る
- 場所：src/main.js:876（`off: … offOk ? 0 : null`）と :885（`f2`）
- 問題：公式想定のセルが無い建物は `off = 0` と置かれ、列に「浸水なし」と表示される。これは「ケース01ではセルなし」であって「浸水しない」ではない（方針P0-3の趣旨・README「『浸水なし』を単独で出さない」に反する）。再現列の「浸水なし」も、この仮定の波でという条件が表に書かれていない。差の計算（sim − off）を 0 基準で出しているため、「差」まで意味のある数字に見える。
- 直し方：セル無しの建物は「セルなし（ケース01）」と書いて差は「—」にする。再現列は「届かず（この仮定）」とし、表の注に「安全という意味ではありません」を足す。

### 中-4　歩く時間を「下限」と呼んでいるが、下限になっていない／丸めが逆
- 場所：src/ui.js:30-37（walkMin、コメントの「これより早くは着かない」）、src/brief.js:62・74（「少なくとも約N分」「まっすぐ歩けたとしての下限」）、README の「歩く時間の下限」
- 問題：
  1. 1.0m/秒は消防庁・国交省とも「目安」「平均的な歩行速度」であり、上限ではない。足の速い人はこれより早く着くので「これより早くは着かない」は成り立たない。
  2. `Math.ceil` は「少なくとも」と逆向きの丸め（3.2分 → 4分は下限ではない）。
  3. 一方、同じ原文には「実際の避難の平均は 0.62m/秒（2.24km/h）」「身体的な歩行速度を上回る値を設定しないこと」とあり、1.0m/秒は「地図で道を知っていてまっすぐ向かえた場合」の値。実態はもっと遅い。
- 直し方：呼び名を「目安」に変える（「1.0m/秒で歩いた場合の目安：約N分。実際の避難の平均はもっとゆっくり（消防庁：0.62m/秒）」）。`ceil` は安全側（遅い側）なので残してよいが「下限」「少なくとも」は外す。0.5m/秒の側は「歩行困難な人・乳幼児など」と原文どおりに書く（いまは「ゆっくり歩く人」）。消防庁の「避難できる距離は最長でも500m程度が目安」を、300m超の見出しの注に添えると原文に沿う。

## 軽微

1. **index.html:119（読み込み中の豆知識）**「1m では全員が亡くなると仮定」：原文は「津波に巻き込まれた人のすべて」。直前の文で主語が「津波に巻き込まれた人」なので誤読は小さいが、「巻き込まれた人は全員」と主語を残すのが原文どおり。
2. **src/ui.js:19（depthSay 最初の文）**：0.01〜0.2m の浅い水にも「（気象庁：20〜30cmでも）」を付けて「浅くても流れは速く、巻き込まれるおそれ」と言う。気象庁の原文は「高さ0.2〜0.3m程度の津波も…」。0.2m未満に出すと原文より強い。「0.2〜0.3mでも」と数字を前に出し、0.2m未満は「浅くても足元に注意」程度に弱めるとよい（強めすぎではあるが安全側）。
3. **src/ui.js:23**「2階の床（約3m）を超える深さ」：出典なし。画面のマーカー（src/render/markers.js:50「2階の床 3m」）とは一致しているが、一次情報ではなくサイト内の目安。「このサイトの目安」と添えるか出典付きの文に置き換える。
4. **「堤防の破損」という言い回し**（src/brief.js:40・42、src/main.js:718・719）：データセット原文は「震度によらず一律に堤防は機能し、堤防を越える津波が襲来した場合その堤防は破壊される」。つまりケース01はすでに「越流で破堤」を含む。画面の「堤防の破損でもっと早く・深く」は、参考データ「堤防03分破壊（地震3分後に破壊）」のような別条件を指すのが正確。「地震の揺れで早く壊れる場合など」と直すと原文どおり。なお「愛知県の想定と同じ条件」（index.html:66、main.js:151・684）の「愛知県」は一次情報を確かめていない。
5. **src/data/official.js:79-84（caseNote）**：内閣府の一覧は整数m（満潮位・地殻変動考慮・市町村別の海岸最大津波高）。`c1 < max` で「最も高くなるケースではありません」は言い過ぎではない（整数同士で c1 が小さければ確実に低い）。ただし `c1 === max` のときは、小数では最大でない可能性が残る。brief.js:23 の非強調側は「ケース01でも最大」と読まれないよう事実の並記だけになっているので問題ないが、「（整数mの表）」と1語添えると正確。代用行（borrowed、20km以内の最寄り）は別の湾の可能性があり、文言は「近くの」で区別されている。
6. **src/data/evac.js:63・src/main.js:501（distJa／mDist）**：995〜999m が「約1000m」と出る（「約1.0km」と揃わない）。見た目のみ。
7. **src/data/official.js:105-113（officialAt の75m）**：自セルが「浸水なし」で隣セルの中心が75m以内だと、隣のセルの深さを「この付近」として返す。浅い側へ誤らず危険側（深く）に出るので実害は小さいが、「100m四方の中心から75m」を条件にしている点を注釈に残すとよい。
8. **src/memo.js:`sheet()`**：印刷する避難メモの公式想定に、「周り300mの浸水」（none のとき）と「ケース01は最大でない」（caseNote）が入らない。画面にはあり、紙には「実際の津波はこれより早く・深くなることがあります」の一般文だけ。紙は残るものなので、none のときの一文（隣の浸水）は紙にも入れたい。
