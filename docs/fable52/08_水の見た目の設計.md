# 3D再現の「水の見た目」の設計　2026-11-10

本人の指示（マネージャAI経由）：「3D 再現するときの、水の感じね。水の感じをもっとフェイブル 5.2 の目線で、もっとリアルな感じにしてください。」

## 1. 守ること

| 守ること | どう守るか |
|---|---|
| 計算の結果（深さ・到達・流れ）と、画面に出る数字を変えない | 変えるのは描画（`src/render/shaders.js`）だけ。浅水方程式（`src/sim/`）には触らない。検証で、同じ時刻の「ここの深さ・最大・流速」が変更前と同じであることを確かめる |
| 深さの読み取り（色分け）を分かりにくくしない | 「深さで色分け」の塗りの式は変えない。凡例と同じ色のまま |
| 「誤った安心をなくす」表示を分かりにくくしない | 札・右の欄・結果画面には触らない。水が浅く・おだやかに見える方向へは変えない（浸水した街の水は、澄んだ水ではなく濁流として描く） |
| 60fps を大きく割らない | ノイズの計算量を今と同じか少なくする。PC幅・スマホ幅で fps を測る |
| ないものを描かない | 漂流物（がれき・車）は計算していないので描かない。泡・濁り・さざ波は、計算した流れ（速さ・向き・泡の場・濁りの場）から決める |

## 2. 変更前の画面で、不自然だった点（Fable 5.2 の目で）

撮影：`water/before_*.jpg`（名古屋港 ガーデンふ頭・高知市 種崎。俯瞰・地点・目線・衝突の4視点、時刻をそろえて撮影）

| # | 不自然な点 | どの画面 | 原因（コード） |
|---|---|---|---|
| 1 | **水面いっぱいに、指紋や木目のような白い細い線**が出る。水というより等高線の版画に見える | 俯瞰・地点（とくに高知） | 泡の「筋」とさざ波を、画素ごとの流れの向きに回した座標で作っている（`fq`・`streak`）。流れの向きが場所で変わると、ノイズの等値線がそのまま線として出る |
| 2 | **街に上がった水が、白っぽい灰色**。濁流に見えず、霧か氷のよう | 目線・地点 | 低い視線では水面がほぼ鏡になり、白い地平線の空だけを映す（フレネル反射が1に近い）。遠くでさざ波を消したぶんの「水面の粗さ」を、反射の強さに入れていない |
| 3 | **浸水した街の水に、茶色い濁りがない** | 俯瞰・衝突 | 濁りは計算の「濁りの場」だけで決めていて、陸へ上がったばかりの水は澄んだ海水として描かれる |
| 4 | **泡が、ヒョウ柄・水玉のような粒の模様**。大きさがそろいすぎている | 衝突・俯瞰 | 泡の模様をセル状のノイズ（同じ大きさの細胞）で作っている |
| 5 | **水の先端が、太い白い帯** | 俯瞰・衝突 | 先端に一律で強い泡を足している。実際の津波の先端は、黒っぽい濁った水が薄く広がる |
| 6 | 泡が、濁った水の上でも真っ白 | 俯瞰 | 泡の色が1色 |
| 7 | 建物の際の暗い帯が、くっきりしすぎ | 衝突 | 一律に0.6倍 |

変えなくてよいと判断した点：海の色（伊勢湾らしい緑がかった灰色）、建物の映り込み、太陽の照り返し、建物の影、浅く澄んだ所の光の網（コースティクス）、飛沫の粒。

## 3. 直し方

| # | 直し方 | ねらい |
|---|---|---|
| A | **白い線をやめる。** さざ波と泡のノイズは、向きを回さない地面の座標のまま、流れで運ぶ（2つの位相を入れ替える流れマップ）。流れの向きは、「流れに沿った傾きを弱める」ことで出す（流れに平行な細長いさざ波になる）。泡は、流れに沿って3点をならして筋っぽくする | 等値線の模様が出ない。流れの向きは、さざ波の伸びと泡の動きで見える |
| B | **水面の粗さを反射に入れる。** 遠く・速い流れほど水面を粗いものとして扱い、真横から見ても鏡にならないようにする（反射の強さの上限を下げ、映す空を少し上にずらす） | 目線の高さでも、水そのものの色（濁り）が見える |
| C | **陸に上がった水は濁流として描く。** 計算の「濁りの場」に加えて、陸の上の水には見た目の濁りの下限を置く（深いほど濃い茶色、薄い所は地面が透ける）。海・運河の水は今までどおり | 街の水が茶色い濁流に見える。海との境目は、濁りの場でなだらかにつながる |
| D | **泡を、大きさのふぞろいな、やわらかい斑（むら）にする。** セル状のノイズをやめ、重ねたノイズのしきい値で作る。泡の量は今までどおり、計算の「泡の場」と、段波の前面・射流・建物への衝突から決める | 水玉模様が消え、波頭や建物際に泡がたまって見える |
| E | **水の先端は、細い泡の線と、濡れた暗い縁**にする（太い白帯をやめる） | 先端の位置は今までどおり読める（線として残る）。白い帯で深さを見誤らない |
| F | 泡の色は、澄んだ海では白、濁流の上では生成り（きなり）色 | 濁流の上の泡が浮いて見えない |
| G | 建物の際の暗がりを、やや弱く、泡と重ならない所だけに | 貼り付けたような帯をなくす |

### 計算を変えないと直らないもの（今回は直さない。相談事項）

- **段波の前面が、巻き込む波（砕ける波の唇）にならない**：浅水方程式は水面を1枚の高さとして解くので、原理的に出ない。描画でごまかすと、ない水を描くことになる。
- **格子（約2m）より細かい水の凹凸**：水面の形は格子の点でしか動かない。細かい凹凸は、法線（光の当たり方）だけで表す。
- **漂流物・がれき・車**：計算していない。描くなら、漂流物の計算を入れるかどうかの判断が要る（防災の表現として誤解を生みやすい）。
- **防潮壁を越える水の落ち込み（滝）**：同上。

## 5. 実装とレビューの結果（2026-11-10）

変えたファイルは `src/render/shaders.js` だけ（水の色を決める関数 `w_water`）。`src/sim/` は無変更。

### 直した内容（最終）

| # | 最終の形 |
|---|---|
| A | さざ波と泡は、地面の座標のノイズを流れで運ぶ（2位相の流れマップ）。流れの向きは、流れに沿った傾きを弱めること、速い流れの「大きなうねり」（8〜15m）、流れに沿って5点をならした幅のある筋（数m幅・数十m長）で出す |
| B | 遠く・速い流れ・濁った水ほど水面を粗いものとして扱い、反射の強さに上限を置く。映す空は少し上にずらす |
| C | 陸（標高データのある所）の上の水には、見た目の濁りの下限を置く（深いほど・速いほど濃い）。**これは計算した量ではなく、見た目の仮定**。海・運河・川は計算の濁りの場のまま。色は暗い灰茶（2011年の市街地の水に寄せた） |
| D | 泡は、重ねたノイズのしきい値で作るやわらかい斑。泡が少ない所は薄いもやだけ。濁った水の上では、白い塊ではなく薄い茶色の泡 |
| E | 水の先端は、細い泡の線。浅い水の下の地面は「濡れた地面」として暗く描く（乾いた地面との境が読める） |
| F・G | 泡の色は海では白・濁流では生成り〜茶。建物の際の暗がりは、水面より上に立つ壁の所だけ、弱く |
| ほか | 陸と海の境は、半径3m・11m・20mの10点でならす（標高データの10〜20mの段が出ないように） |

### 確かめた結果

| 項目 | 結果 |
|---|---|
| 計算の数字 | 同じ時刻の「ここの深さ・最大・流速・水の先端」が、変更前後で**完全に同じ**（名古屋PC幅 4時点・名古屋スマホ幅 2時点・高知 2時点。`water/before_report.json`・`after_report.json`）。計算の進め方を、描画の重さや実時間に左右されない形（8コマずつ進め、GPUの処理の終わりを待つ）にそろえて比べた |
| 色分け | 「深さで色分け」は変更前と同じ色（`water/*_over_depthcolor.jpg`） |
| fps | 名古屋PC幅（格子768²）4視点とも60／スマホ幅（格子512²）60／高知は目線・衝突60、俯瞰は回により39〜60（変更前も42。再生再開直後の最初の計測で揺れる） |
| 1コマの描画時間 | 垂直同期に左右されない計測（止めたまま90コマ描いてGPUの終わりを待つ）で、変更前後とも約1.0〜1.5ms。差は計測のばらつきの範囲（`water/bench.txt`） |
| 回帰 | 通し確認（PC・スマホ幅・内陸の二段計算・高知）でコンソールエラー0・60fps。`npm run build` 成功 |

- **動いている画面での見え方**（3秒周期の入れ替わりのちらつき、泡の動き）：静止画での確認だけ。本人の目で、実際の画面を見ていただきたい。

- 「計算を変えないと直らないもの」（3章）：巻き込む波、格子より細かい水面の凹凸、漂流物、防潮壁を越える水の落ち込み。入れるかどうかは相談事項。
