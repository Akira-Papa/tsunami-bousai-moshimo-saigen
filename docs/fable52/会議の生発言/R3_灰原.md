# R3 灰原ことは

## (1) 同意と異議
裁定1・4・5・7は同意。裁定2は出典確認後のみに同意。ただし1km圏の5件は遠い建物へ歩かせかねないため、各件に「直線○m」を付け、最初は3件まで表示します。裁定3は、私の「次回」案を取り下げ、同意します。

**「この地点の公式想定」カード**（`#sel` 内、地点名の直下、海の高さの上）の並び順：
1. 公式の最大浸水深（大きな数字）と、地震から最早到達の一行。0.3m・1m・2mの目安は文字で添える。
2. 指定緊急避難場所（津波）を3件。名前と直線距離だけで、残りは「ほかN件」に畳む。
3. 標高は地点名の補足へ。「予測ではありません」の一行は見出しに。

スマホ390幅では、このカードを `.sel-place` の次に置き、その下に出典・条件一行と `<details>`（くわしい条件）を並べます。`.go-bar` は固定のままです。

## (2) 落とし穴
1. **非同期の取り違え。** main.js:36〜46は非同期で値を取るので、前の地点の値が残ったり、読み込み中の空欄が「浸水なし」に見えたりします。読み込み中は「確認中…」、古い応答は破棄、4状態は文言で分けます。`aria-live` はカード1か所に、完了時の1回だけにします。
2. **色だけ・Tabで届かない。** 地図の円は色だけでは区別できないため、同じ内容をカードの文字にも出します。避難場所の一覧は `<button>` にし（`.results li`、style.css:46の轍を踏まない）、押すと地図が動き、`:focus-visible` も付けます。
3. **3Dボタンが使えない理由が見えない。** `#go` を無効にするだけでは分かりません。直上に「この端末では3D再現は使えません。公式想定は上のカードで見られます」と書き、`aria-describedby` で結びます。`#nogpu`（index.html:188）は廃止します。
