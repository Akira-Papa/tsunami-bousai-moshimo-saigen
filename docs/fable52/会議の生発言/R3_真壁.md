# R3 真壁 澪

## (1) 同意できない点
裁定1〜3・6〜11は同意。裁定4・5と1の一部に修正を求める。
- **裁定4**：1km・5件は可。ただし「近い順」は最短の逃げ先に読める。直線距離は、川・運河をまたぐと道のりが大きく変わる。文言は「直線距離。川・運河・線路をまたぐ場合、道のりは大きく変わります。海や川に近づく向きかも地図で確認」とする。見つからないときは「このデータには見つかりませんでした」とし、「避難先がない」とは書かない。
- **裁定5**：高さ余裕の注記は、比べる水位の範囲が合っていない。水位は300m以内の最大（main.js 661〜670）で、1kmの緑は比較先がない。代案：比較できる緑（水位があり、高さが分かるもの）だけ「この再現では水位に対し余裕2m未満」と警告し、それ以外は「再現の水位との比較はしていません」と書く。「余裕2m以上」と肯定する表示は出さない。2mは公式の基準ではなく**未確認**の仮の目安。
- **裁定1**：公式の「約108分」はケース01の最早到達であり、11ケース全体の最短ではない。「ほかのケースではもっと早い可能性があります」を添える。

## (2) 落とし穴（最大3つ）
1. **緑の高さ判定。** 383行の `hEff` は建物の高さで、校庭・高台の避難場所は建物がなく、`hEff` が null になる。これを「余裕なし」にすると誤警告になり、null を「余裕あり」にすると誤安心になる。比べるのは地盤標高＋建物高とT.P.水位（385行の式）で、不明なら不明と表示する。全国の緑は PLATEAU の建物に結び付かないので、高さは出せない。370・372・662行の半径300mも広げ漏れやすい。
2. **13分の削除範囲。** 563行は到達の表示だけでなく `st.arrived` を立て、533行の「水が引かない土地」の判定に使う。566行の `st.closest` は632行の「最も近くて約…」が使う。表示行だけ消し、状態は残すこと。
3. **文言の肯定表現。** 「見つかりませんでした」「浸水セルなし」「届かなかった」の語尾が、安全の宣言に変わらないよう、毎回「安全という意味ではありません」を同じ枠内に置く。
