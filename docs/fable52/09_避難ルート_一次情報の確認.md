## 1. PLATEAU の道路モデル（本人の問い「道のデータは国が公開していないか。PLATEAUで」）

### (a) 標準製品仕様書での定義【一次】
出典：3D都市モデル標準製品仕様書 第5.0版 4.3節 https://www.mlit.go.jp/plateau/file/libraries/doc/plateau_doc_0001_ver05.pdf
- LOD0：「道路の形状を線により表現する。…ネットワーク（道路中心線）又は道路縁のいずれか」。原則は中心線。空間属性 `tran:lod0Network`（道路の場合は「道路の連続性を表現する線」）。
- LOD1：「道路の形状を面により表現する」。道路縁で囲まれた面を、交差部・道路構造変化箇所などで区切る。高さ0。
- LOD2：面を「車道部、車道交差部、歩道部及び島に区分」。LOD3：車道部・交差部・歩道部・分離帯等に区分（LOD3.0〜3.4）。
- ノード・リンクの位相：道路モデルの定義には「ノード／リンク」クラスは無い（tran:Road の位相は仕様に出てこない。ノード・リンクが出るのは都市設備の uro:UtilityLink 等のみ）。つまり「交差点でつながる道の網」としての位相は標準では持たない。LOD0 の中心線も GeometricComplex（線の集まり）であり、ルーティング用グラフとは定義されていない。【一次】

### (b) 名古屋市（2022年度）【一次】
出典：G空間情報センター https://www.geospatial.jp/ckan/dataset/plateau-23100-nagoya-shi-2022
- 「交通（道路）モデル（LOD1）：CityGML形式、MVT形式」。LODは1のみ（LOD0中心線もLOD2歩道も無い）。最新版は製品仕様書V4（2025-03-21追加）。

### (c) 配布形式と実行時配信
- 配布：CityGML ZIP（v4は約2.78GB）、3D Tiles/MVT ZIP（v4は約1.65GB）。【一次/HEAD実測】ブラウザで丸ごと取る用途には不向き。
- 実行時に必要範囲だけ取れる配信：あり。PLATEAUカタログAPI `https://api.plateauview.mlit.go.jp/datacatalog/plateau-datasets` に名古屋の `23100_tran_lod1`（type_en=tran, format=MVT, lod=1, layers=["Road"]）。TileJSON `https://api.plateauview.mlit.go.jp/datacatalog/mvt/23100-tran-lod1-2022/tilejson.json`（z10〜16、タイルURL `https://assets.cms.plateau.reearth.io/assets/bf/376fe4-747a-48a6-b119-5f63c4c44d3b/23100_nagoya-shi_city_2022_citygml_4_op_tran_mvt_lod1/{z}/{x}/{y}.mvt`）。タイルは `access-control-allow-origin: *`（CORS可）。【実測】
- 配信は「試験的な運用であるため、提供期間やサービスレベルについては保証できない」旨（plateau-streaming-tutorial。現行は https://docs.plateauview.mlit.go.jp へ移行）。【一次】
- 実測（z16 タイル 57684/25926）：200件すべてがポリゴン（geomtype=3）、属性は tran:function/usage、uro:width（実数 m または -9999）、widthType、gml_id 等。線もノードも無い。【実測】

### (d) 利用条件【一次】
出典：PLATEAU サイトポリシー https://www.mlit.go.jp/plateau/site-policy/ ／データセットページ
- 「公共データ利用規約（第1.0版）（PDL1.0）」準拠、「CC BY（表示4.0）と互換性があります」。出典例「出典：国土交通省 PLATEAUウェブサイト（当該ページのURL）」。編集・加工した場合は別途その旨を記載、「あたかも国土交通省が作成したかのような態様」は不可。免責あり。商用可・無償。

### (e) 歩行空間ネットワーク等
- PLATEAU内：LODの定義に tran:Track（徒歩道、LOD0は中心線ネットワーク）はあるが、名古屋2022のデータセットには含まれない（上記LOD1道路のみ）。【一次】
- PLATEAU公式の道路ネットワーク生成ツール（PLATEAU-RoadNetwork-Generator）：3D都市モデルから「ノード／リンク」を shp/GeoJSON で出力。Windows GUI、LGPL-2.1、「動作保証は行っていません」。ブラウザ実行時ではなく事前変換用。【一次（README）】
- 国土交通省「歩行空間ネットワークデータ」（ほこナビ hokoukukan.go.jp）：仕様上は「リンク」と「ノード」で構成。名古屋市のデータが e-Gov データポータルに掲載（gml/csv/描画地図、ライセンス「政府標準利用規約（第2.0版）」、最終更新2025-08-01）。ただし整備範囲は「名古屋市」とだけで、市内全域かは不明。ほこナビのページはcurlが403、WebFetchで一部のみ確認。トップページの整備例は東京・川崎・高松・鯖江など。【一部一次・範囲は未】

### 結論（1）
PLATEAUの道路モデルは、名古屋では LOD1 の「面」のみで、ノード・リンクの位相が無く、そのままでは最短経路に使えない。使うには面から中心線・ノード・リンクを作る前処理（公式ツールを使うなら Windows 上でオフライン実行→自前でタイル／JSON化）が必要。

## 2. 国土地理院ベクトルタイル提供実験（experimental_bvmap）の道路（road）

出典：GitHub README https://github.com/gsi-cyberjapan/gsimaps-vector-experiment ／ 属性一覧 https://maps.gsi.go.jp/help/pdf/vector/attribute.pdf（令和7年11月21日更新）／ 地物コード一覧 https://maps.gsi.go.jp/help/pdf/vector/dataspec.pdf（ZL14〜16は令和4年10月6日更新）。すべて【一次】、タイルの数値は【実測】。

### (a) 属性の定義
- ftCode：地物種別コード（ZL8〜17は4桁）。dataspec より：2701=道路-通常部-通常部、2702=雪覆い、2703=橋・高架、2704=トンネル、2711〜2714=庭園路（通常部/雪覆い/橋・高架/トンネル）、2721〜2724=徒歩道、2731〜2734=石段。
- 2201・2221 など22xx系：dataspec では「ズームレベル17」表（列見出しは ZL16 と誤植らしい）の道路に出てくるコード（道路-通常部/庭園路）。実測では z16 タイルに 2201（72本）・2221・2223・2411 が出て、rdCtg 等の属性が無い。道路縁（真幅道路の縁線）である可能性が高いが、仕様の文言では確定できない。2411は仕様表で特定できず。【未】
- rdCtg：0=国道、1=都道府県道、2=市区町村道、3=高速自動車道等、5=その他、6=不明
- motorway：0=高速道路以外、1=高速道路、9=不明
- rnkWidth：0=3m未満、1=3m以上5.5m未満、2=5.5m以上13m未満、3=13m以上19.5m未満、4=19.5m以上、5=その他、6=不明
- lvOrder：「道路の階層順」（値の意味の表なし。実測は0がほぼ全て、1が少数＝立体交差の上下関係と推測【未】）
- Width：「道路の実幅員」（整数）。medSect：0=分離帯無し、1〜98=分離帯幅(m)、99=幅員急変等非表示。tollSect：0=無料、1=有料、2=暫定無料、9=不明
- 実測：rdCtg は実データで 1/2 のみ、motorway は 9 が大半（名古屋の2タイル）。値が不明(9)だらけなので属性に依存した判断は避ける。

### (b) ズームレベル
- README：「ズームレベル4〜16。ズームレベル17の情報は16に含んだうえでオーバーズーム」。ベクトルのzはラスタより1小さい（ベクトル14〜16＝ラスタ15〜17）。実測：z17 は404。
- z14・z15・z16とも道路の線が入る。ただし z16 の線は 2701（属性付き中心線）に加え属性なしの 22xx 系が混在。名古屋の z14 で道路2285本、z15（9タイル）で約5000本の 2701。

### (c) 交差点で分割されているか
- 公式にそれを明記した文は確認できず【未】。実測（z14, z16 の各1タイル）：ある線の端点が別の線の途中の頂点に載っている（T字で未分割）ケースは0件。中心線は交差点（端点）で分割されていると見てよいが、タイル境界で線が切れ、立体交差（lvOrder）や端点の座標一致の許容を自前で処理する必要がある。ネットワークとしての保証は無い。【実測】

### (d) 利用条件【一次】
- README：国土地理院コンテンツ利用規約に従う。「データを利用する際は、「国土地理院ベクトルタイル提供実験」などと、出典の明示」。「提供実験中のデータであるため、URL やデータ構成、データの内容（属性の有無や名称等）が変わる可能性があります」。「基本測量成果と位置付けているものではありません」。「損失及び損害等について…責任を負わない」。データソースは「数値地図（国土基本情報）- 地図情報 等」。
- 利用規約（https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html）：PDL1.0適用、出典記載、編集・加工は別記、「あたかも国土地理院が作成したかのような態様」は不可。
- 測量法の承認：bvmap は README 上「基本測量成果ではない」。地理院タイル一覧（https://maps.gsi.go.jp/development/ichiran.html）にも bvmap は載っておらず、同一覧は基本測量成果タイルでもウェブサイトでリアルタイム読込なら出典のみで申請不要と説明。経路線を自前のWebサイトに描く用途が「複製・使用」に当たるかの明文は確認できず【未】。出典明記＋加工の旨の併記＋実験提供である旨の免責を推奨（法的判断ではない）。

### (e) 徒歩道・石段・庭園路
- 仕様上は別ftCode（2721〜2724、2731〜2734、2711〜2714）で収録。ただし実測では名古屋の z15 9タイルで 2721（徒歩道）が1本、石段は0、庭園路は約200本。歩行者専用の細道は薄い。

## 4. 「高台」「避難目標地点」の公的な考え方
出典：消防庁「津波避難対策推進マニュアル検討会報告書」（平成25年3月）https://www.fdma.go.jp/singi_kento/kento/items/kento106_01_p0.pdf 、用語（p.14）ほか。【一次（全文検索）】
- 避難対象地域：「津波が発生した場合に避難が必要な地域で、津波浸水想定区域に基づき市町村が設定する。…津波浸水想定区域よりも広い範囲で設定する。」
- 避難目標地点：「津波の危険から避難するために、避難対象地域の外に定める場所をいう。…必ずしも指定緊急避難場所とは一致しない。」「避難対象地域の外縁と避難路、避難経路との接点付近となる」「袋小路…背後に階段等の避難路…がない急傾斜地や崖地付近は避ける」
- 指定緊急避難場所：「津波の危険から緊急に避難するための高台や施設などをいう。原則として避難対象地域の外に定める。」
- 避難可能距離：「＝（歩行速度）×（津波到達時間－避難開始時間）」。歩行速度は「1.0ｍ／秒…を目安」、弱者は0.5ｍ／秒、東日本大震災の実態平均は0.62ｍ／秒。「避難できる限界の距離は最長でも500ｍ程度を目安」。避難開始は地震後2〜5分を想定。
- 経路：「海岸沿いや河川沿いの道路…はできる限り避ける」「海岸方向への避難は避ける」。「必ずしも指定緊急避難場所への最短コースを避難する必要はなく…避難対象地域の外に最も安全かつ早く避難できる…最短コース」。
- 避難ビル：内閣府「津波避難ビル等に係るガイドライン」は公開されているのは検討会の（案）資料のみ確認（https://www.bousai.go.jp/kohou/oshirase/h17/pdf/050323shiryou2.pdf）。「3階建て以上（想定される浸水深が1m以下であれば2階建てでも可）のRCまたはSRC」「浸水深2mを想定したもの。3mの場合は4階建て以上」「避難スペースは…想定される津波の最大浸水深を考慮して、安全性が確保できる高さ」。最終版の本文は未確認【未】。上記報告書にも「想定浸水深相当階の２階上以上…又は、基準水位以上の室内」の記載。
- 基準水位（津波防災地域づくり法 第53条第2項、e-Gov）：「津波浸水想定に定める水深に係る水位に建築物等への衝突による津波の水位の上昇を考慮して必要と認められる値を加えて定める水位であって、津波の発生時における避難…の基準となるべきもの」。【一次】
- 指定緊急避難場所データ（skhb05）に「高台」の区別：無い。属性は name・address・remarks（市町村の参考情報）・disaster1〜8のみ（GSI 一覧の仕様）。【一次/実測】

## 5. 気象庁の遡上高
- 名古屋地方気象台（気象庁）https://www.data.jma.go.jp/nagoya/shosai/info/mini-jishin/tsunami_height.html ：「気象庁が津波予報で発表する「津波の高さ」は、海岸付近での津波の高さのことで、津波が陸地を駆け上がった高さ（遡上高という）とは異なります。」「一般的に、津波の「遡上高」は海岸付近での「津波の高さ」の２倍〜４倍に達することが多く、Ｖ字谷のような特殊な地形の場所ではさらに高くなることがあります。」【一次】
- 気象庁FAQ https://www.jma.go.jp/jma/kishou/know/faq/faq26.html ：「「予想される津波の高さ」は、海岸線での値です。」遡上高の定義「海岸から内陸へ津波がかけ上がった高さ」、東北沖で「局所的に40.1mの遡上高」。【一次】
- 依頼文の「同程度から4倍程度」という文言は、確認した気象庁ページには見当たらない（「２倍〜４倍に達することが多く」が実際の文言）。【未】

## 6. skhb05 の属性（実データ）
https://cyberjapandata.gsi.go.jp/xyz/skhb05/10/901/405.geojson を取得：1692件すべて Point。properties は name・address・remarks・disaster1〜7 のみ。標高・階数・高さの属性は無い。remarks は18件のみ（例「「洪水、高潮」では上層階に避難」＝津波用の高さ情報ではない）。【実測】
GSI 仕様：「name 施設・場所名／address 住所／remarks 備考（各市町村が付した参考情報）／disaster5 津波」、「最新でない場合や未掲載の場合があるため、最新かつ詳細の状況などは必ず当該市町村にご確認ください」。

## 設計への結論
- 道の元データ：鍵不要でブラウザから取れて線の道路網に近いのは国土地理院 experimental_bvmap の road（2701等＝中心線、z14〜16、CORS可、実測で交差点分割済み）。ただし「提供実験」で仕様変更の可能性があり、立体交差・タイル境界・細道の薄さへの自前対応と、取得失敗時の逃げ道が要る。
- PLATEAU道路モデル：名古屋はLOD1の面のみでノード・リンクが無く、そのまま最短経路には使えない。使うなら事前に中心線・グラフへ変換（オフライン処理）が必要。当面は「経路計算には使わず、補助表示や幅員（uro:width）の参考」に留める。
- 歩行空間ネットワーク（国交省）：名古屋市分の存在は二次的に確認、範囲と形式・規約は一次で未確認。ブラウザ直読みの配信は未確認のため設計の前提にしない。
- 高台の定義：公的資料に沿うなら「避難目標地点＝避難対象地域（津波浸水想定区域より広い）の外」。標高の閾値だけで高台と定義しない（遡上高は海岸の津波の高さの2〜4倍に達することが多い）。skhb05は高さを持たないので、避難場所を「高台」「安全な高さ」と断定できない。
- 画面に書いてよいこと：「地理院ベクトルタイルの道路線をたどった目安の道のり」「消防庁の目安（歩行1.0m/秒、2〜5分後に開始、最長500m程度）に基づく概算」「最新は市町村に確認」。出典の明示。
- 書いてはいけないこと：「ここなら津波は来ない／安全」「標高が海岸の津波高より高いから安全」「最短で必ず着く」「道は通れる」（石段・細道・通行止め・浸水・崖は保証できない）。到達時間が確定した値であるかの表現、PLATEAU道路を経路に使っているとの記載、避難場所を高台と断定する表現。
