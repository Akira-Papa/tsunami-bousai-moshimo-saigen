## 1　何を直したか（ひとことで）

| | 直したこと | 直す前 |
|---|---|---|
| 水の流れ | 水の上に「流れの印」（白い細い線）を出す。向き＝明るい先、速さ＝長さ。計算した流れに乗って動く | 水が動いているのか、どちらへ流れているのかが、絵から読めなかった |
| 水の流れ | 水のふちに、明るい線（深さ約5cmの所）を出す | 水がどこまで来たかが、遠目に分かりにくかった |
| 水の流れ | 再生の速さ「おまかせ」（既定）。ふだんは×20（内陸は×60）、水が防潮壁を越えた時・地点に近づいた時だけ×5にして知らせる。［×20のまま］で止められる | ×20固定。大事な場面が数秒で過ぎた |
| 計算 | **同じ条件なら、何度やっても・どの速さで再生しても、同じ数字になる**ようにした | 再生の速さや端末の速さで、数字が数%動いた |
| 計算 | 「×1」が本当に×1になった | 実際は×1.3〜×2で進んでいた |
| 計算 | 最大の流れの速さを、深さ5cm以上の水だけで測る | 先端の薄い膜（深さ5mm〜1cm）の一瞬の値を拾っていた |
| 計算 | 試験を3つ足し、2つを厳しくした（下の4） | 水際が動く問題の試験がなかった |
| 正直さ | 結果の画面に「近くの海岸の水位（計算で届いた最大）」を出す。仮定の高さに届かなかった回は、赤い注意で知らせる | 届かなかったことが、どこにも出なかった |
| 正直さ | 結果の「条件」に「高い水位が続く時間 15分（長めの仮定）」を出す | 出ていなかった |

変えなかったもの：波の形（600秒で上がる）、計算の箱の大きさ（1.5km四方）、防潮壁の切れ方（越えられたら、その場で壊れる）。理由は下の「5　仮定を量った結果」。

### 名古屋駅の近く（内陸・二段の計算。広い計算＋地点周り1.5km四方）

この地点には、計算の終わり（約84分）まで水が届きません（直す前も後も同じ）。比べられるのは、広い計算の数字です。

| 数字 | 直す前（2回） | 直した後（×60を2回） |
|---|---|---|
| 水の先端までの距離（約3000秒） | 5936m・5939m | 5937m・5937m |
| 同（約5000秒） | 4619m・4632m | 4632m・4632m |
| 沖の波を合わせる係数（約3000秒） | 0.490 | 0.490 |

**注：最大の流れの速さ**　この数字は、水の先端が着いた直後の短い山の値で、条件のわずかな違いに敏感です。直す前は、記録の間隔が画面の1コマごと（再生の速さで変わる）だったため、山の頂上を拾えるかどうかで 1.76〜1.90 と動いていました。直した後は、決まった間隔（計算の約0.3秒ごと）で記録するので、どの速さでも同じ値です。前の幅より1〜2%大きいのは、山の頂上に近い所を毎回拾うようになったためと考えています（推測）。あわせて、深さ5cm未満の薄い膜では速さを記録しないようにしましたが、この2地点では、その前後で値は変わりませんでした（山は薄い膜の値ではなかった）。

**数字が変わった理由のまとめ**
1. 沖の波の大きさを合わせる計算（海岸の水位を読んで係数を直す）を、決まった時刻（計算の時計で約15秒ごとに読み、その約5秒後に効かせる）にした。直す前は、読んだ値が届いた時に直していたので、端末や再生の速さで時刻がずれた。
2. 沖の波の高さの更新・最大の記録・防潮壁が切れる判定・木造家屋が流される判定を、決まった間隔（計算の約0.3秒ごと）にした。直す前は、画面の1コマごと（再生の速さで間隔が変わる）だった。
3. 二段の計算では、広い計算が1歩だけ先に進み、細かい計算が追いつく、という組み合わせを固定した。直す前は、広い計算が1コマぶん（最大約1秒）先に進んでいた。
4. 最大の流れの速さは、深さ5cm以上の水だけで測る。
5. 名古屋の「着く時刻」が前の幅より1秒遅いのは、1の「約5秒後に効かせる」ぶん、沖の波の調整がわずかに遅れるためと考えています（推測。読んだ時点で待って効かせる作りでは 812.3秒で、前の幅の中でした。待つ作りは、約15秒ごとに水が1〜2コマ止まって見えるので、やめました）。深さ・速さへの影響は1%未満です。

**参考：格子の細かさによる違い（直す前からある性質）**　名古屋港を、格子 768²（1マス約2.0m）と 512²（約2.9m）で比べると、最大の深さは 1.729m と 1.719m（0.6%の差）ですが、水が着く時刻は 814.7秒 と 936.2秒 で、約2分ちがいます。防潮壁を越える水の量が、マスの大きさで変わるためと考えています（推測）。画面では、着く時刻は今までどおり出していません。

同じ地点を、仮定を1つだけ変えて計算した（格子は約2.9m。3kmの箱だけ、画面の決まりで約2.3mになった）。基準は、測る前に設計書で決めたもの。

| 仮定 | 名古屋港：最大の深さ | 高知 種崎：最大の深さ | 基準 | 決定 |
|---|---|---|---|---|
| いま（箱1.5km・高い水位900秒・壁はその場で壊れる） | 1.719m | 11.368m | — | — |
| 箱を3km四方に | 1.563m（**−9.1%**） | 13.025m（**+14.6%**） | 20%より大きく動けば、沿岸も二段計算に | **変えない**（20%以内）。差を記録 |
| 高い水位を300秒に（いまは900秒） | 1.012m（**−41%**） | 10.607m（−6.7%） | 15%より大きく動けば、条件に書く | 結果の「条件」に「高い水位が続く時間 15分（長めの仮定。短いと、深さは浅く出ます）」を出した。数字は変えない |
| 防潮壁が120秒かけて壊れる（いまは、その場で） | 1.708m（−0.6%） | （防潮壁なし・同じ） | 既定は「その場で」のまま | **変えない**。流れの速さは −9.7%、着く時刻は +13秒 |

正直に書いておくこと：
- 箱を3kmにすると、**最大の流れの速さ**は 名古屋 1.73→2.12m/s（+22%）、高知 3.10→4.10m/s（+32%）と、深さより大きく動いた（設計の見込みは ±15%）。流れの速さは、箱の大きさと格子の細かさに敏感な数字です。結果の画面の「最大の流れの速さ」は、この幅をもった目安として読んでください。
- 箱を3kmにした名古屋では、沖の波を合わせる係数が上限（1.3）に張り付き、近くの海岸の水位は 4.84m（仮定5.0m）までしか上がらなかった。箱を広げると、仮定の高さの波を入れにくくなる地点がある。
- 3kmの箱は格子が約2.3mと細かく、「箱の大きさ」だけの違いにはなっていない。

## 6　近くの海岸の水位が、仮定の高さに届かない地点がある（今回見つけて、表示を足した）

別役のレビューで見つかった点。高知駅の近く（北緯33.5672・東経133.5436。箱3.8km四方・格子1280²・海の高さ15m）では、沖の波を合わせる係数が上限（1.3）に張り付いたまま、近くの海岸の水位は 1500秒で約7.0m（仮定15mの約半分）までしか上がらなかった。湾の奥にある地点で、箱の中の海が狭い入口の向こうにあるためと考えています（推測）。

直す前は、このことが画面のどこにも出ず、「15mの波でも、ここには水が来ない」と読めてしまう状態でした。直した後は：
- 結果の画面に、いつも「近くの海岸の水位（計算で届いた最大）T.P.+○m（仮定は○m）」を出す。
- 仮定の9割に届かなかった回は、結果のいちばん上に「この再現では、近くの海岸の水位が、仮定の高さ（○m）まで上がりませんでした（計算で届いたのは 約○m）。ここに出ている深さは、仮定どおりの高さの波が来た場合より、浅く出ています。安全の根拠にはなりません。」を出す。

計算そのもの（係数の上限・波の入れ方）は変えていません。上限を上げると、箱の縁で20mを超える波を作ることになり、縁の近くの結果を壊すためです。届かない地点でどう計算するかは、残る課題です（下の「9」）。
