# 14　3Dの「逃げる道のり」の帯 — 結果（D5）

2026-11-11　設計：[11_水の流れ・計算・画面・3D地図の設計.md](11_水の流れ・計算・画面・3D地図の設計.md) の D5（優先3）。
「13」で次の作業として見送った項目を、Fable 5.2 の担当スレッドが週の上限で止まったため、マネージャAI（Opus 5.5）が引き継いで実装した。

## 1　何をしたか

| 項目 | 内容 |
|---|---|
| 帯 | カードで求めた道のり（国土地理院ベクトルタイルの道路中心線・浸水する道も避けない）と同じ道を、3Dの地面の上に帯で描く。色は2Dの地図と同じ：緑＝指定の逃げる場所まで、橙＝標高が高い所まで、白い細いふち |
| 水の下の区間 | いま水が来ている所（描いている水の深さ 約5cm以上）は、**灰色の点線**にする。消すと「道がない」、色の実線のままだと「水の中を通れる」と読まれるため（設計 D5 のとおり）。水面の少し上に描く |
| 建物の陰 | 家の密集した町（尾鷲など）では、帯が屋根に隠れて途切れる。陰の部分も薄く（3割の濃さ）透けて見えるようにした。屋根の上を通るように見えないよう、薄さで区別する |
| 太さ | 画面の上で数ピクセルになるよう、カメラからの距離で太さを変える。カードで選んだ1本は太く、ほかは薄く |
| 行き先の札 | 指定の逃げる場所は 2Dと同じ A・B・C、高い所は「高い所（標高 約○m）」 |
| 切替 | 「表示」の中に「逃げる道のり（カードと同じ道）」。既定はオフ。**カードで道のりを選んでから3Dに入ったら、自動でオン**（設計 D5 のとおり） |
| 凡例 | オンの時だけ、下の操作欄に「緑＝指定の逃げる場所まで／橙＝高い所まで／点線＝いま水の下」と「逃げるのは、水が来る前です。通れるとは限りません。」 |
| 範囲の外 | 計算した四角の外は描かない（外の水は計算していないので、乾いているとは言えない）。外へ出る道がある時は「計算した範囲の外の道は、描いていません。」と出す |
| 波の高さ | 高い所の行き先は、カードで求めた時の海の高さで決まる。3Dの条件で海の高さを変えて入った時は、高い所の帯は出さず、指定の逃げる場所の帯だけ出す（海の高さに関係しないため） |

| 「水の下」の決め方 | 道の各点で、そのマスと上下左右4マスの、描いている水の深さのいちばん深い値から、**再現が始まった時にすでにあった水を差し引いて**、5cm以上なら点線（水のふちの明るい線と同じ深さ）。始まった時の水は、最初の数コマを描いたあとに一度だけ計算の値を読み戻して覚える |
| 橋 | 川・運河・港の水の上を通る区間（地図で最初から水のマス）は、下の水では決めず、**いちばん近い岸の点**の水で決める。帯の高さは両岸の地面の高いほう（橋の高さのデータはない） |
| 建物のマス | 道の線が建物の形に乗った所（高架の下など）は、いちばん近い建物でないマスで決める。堤防・水門・壁のマスは、周り4マスの水を見る |
| 遅く届いた時 | 道のりが届いたのが、再現が進んでから（計算の時計で2分を過ぎてから）だった時は、始まりの水を読めないので、3Dには出さない（切替の説明にその旨を出す） |

ファイル：`src/render/routes3d.js`（新規）、`src/main.js`（組み込み・切替）、`src/brief.js`（道のりを3Dへ渡す）、`index.html`（切替・凡例）、`src/style.css`。

## 2　変えなかったこと

- 道のりの求め方（`src/route.js`）と、2Dの地図の線。3Dはカードの結果をそのまま使う。
- 計算（水）には何も足していない。帯は、水面を描く時と同じ数字（各マスの水の高さ・深さ）を読むだけ。

## 3　別役のレビュー（コード）と、その反映

| 指摘 | 重さ | 反映 |
|---|---|---|
| 川・運河・港の上の橋が、波が来る前から「いま水の下」の点線になる（もともと水のあるマスの深さだけで決めていた） | 重大 | 橋の区間は近い岸の点で決める。帯の高さは両岸の高いほう |
| 建物・堤防・水門のマスを通る区間は、周りが深く浸かっても実線のまま（壁のマスは「乾いている」扱い） | 中 | そのマスと上下左右4マスの最大で決める。建物のマスは近い建物でないマスで決める |
| 「水の下」の基準（3〜10cm）が、水のふちの明るい線（約5cm）と合っていない | 中 | 2〜5cmで点線に切り替える |
| 確認スクリプトが、札が見えていなくても・水が届かなくても合格になる。「水の下で点線になる」ことを数えていない。404 をすべて見逃す | 中 | 見えている札だけ数える／水が届かなければ不合格／読み戻した計算の値で「波の前は0点・着いた後は1点以上」を数える／404 は国土地理院の標高タイルだけ見逃す |
| 行き先の札が、高い所の2つで同じ文言 | 軽微 | 「海の高さより上」「海の高さの2倍より上」と標高を出す |
| 道のりを求められなかった時、切替の説明が「求めている間」のまま | 軽微 | 理由に合わせた説明に変える |
| 遅く届いた道のりを、別の地点のカードから描くおそれ | 軽微 | 始めた時と同じカードの時だけ描く |

レビューで見つけていない点を、マネージャAIが追加で直した：満潮で始まる地点（名古屋港）では、潮位より低い岸壁が最初から濡れていて、そこを通る道が波の前から点線になる → 始まった時の水を差し引く（上の表「水の下の決め方」）。

## 4　確かめた結果

自動確認：`scripts/fable52/route3d.mjs`（名古屋港 ガーデンふ頭。記録と画像は [route3d/](route3d/)）

| 確かめること | PC 1440×900 | スマホ 390×844 |
|---|---|---|
| カードでAを選んでから3Dに入ると、自動でオン・凡例が出る | 合格 | 合格 |
| 何も選ばずに入ると、オフのまま。「表示」から入れられる | 合格 | 合格 |
| **波が来る前は、道のどこも「水の下」と読まれない**（読み戻した計算の値で数える） | 0点 / 796点 | 0点 / 542点 |
| **水が地点に着いた60秒後は、道の一部が「水の下」と読まれる** | 606点 / 796点 | 471点 / 542点 |
| 行き先の札 | 「A」が画面に出る | 3つとも作られる。最初の視点では画面の外（建物の【指定】の札は見えている） |
| 地点が欄や操作に隠れない | 合格 | 合格 |
| 凡例が出ている時の3Dの見える面積 | 65.3% | 63.8%（55%以上） |
| コンソールエラー（地理院の標高タイルの404を除く） | 0 | 0 |

これまでの確認：道のりの確認（`route.mjs`）名古屋・尾鷲・串本・通信断 すべて合格・エラー0。通し確認（`verify.mjs`）11条件 エラー0（スマホ幅の1条件は、ほかの確認と同時に走らせて待ち時間を超えたため、単独で走らせ直して エラー0）。ビルド成功。

ブラウザでの目視（マネージャAI）：名古屋港で、乾いた公園の区間は緑の帯のまま、水の下の区間は明るい灰色・濃いふちの点線になり、水のふちの明るい線の所で切り替わる。尾鷲（家の密集した町）で、橙の帯が建物の陰でも薄く続く。点線は、最初は凡例と同じ暗い灰色にしたが、濁った水の上で沈んで見えにくかったため、明るい灰色に濃いふちを付けた。

## 5　確かめていないこと

- 実機のスマートフォンでの見え方。
- 「点線＝いま水の下」が、初めて見る人に「水の中は通れない」と正しく読まれるか（別役の画像レビューは、今回は回していない）。
- 計算の四角の外へ続く道（尾鷲の高い所など）は、外の部分を描いていない。
