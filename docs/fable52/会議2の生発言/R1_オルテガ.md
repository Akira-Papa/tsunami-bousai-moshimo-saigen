# R1 オルテガ（A：水の流れ）

結論：筋やうねりでは「向き」は出せない。**流れを運ばれる印（粒子の尾）で出し、時間のものさしを合わせる**。

## 1. 伝わらない原因（上位5）
1. **時間のものさしの食い違い**。`w_water` の流れマップは実時間（env.y=now/1000、T=3秒）で流速どおり動く。再生は×20なので先端は秒速60m相当、筋は秒速3m。飛沫も `pack(pdt)` で実時間。`over_1100s`・`pin_1100s` は一面の茶色の板で動きが読めない。
2. **向きの符号が絵にない**。`g -= fd*dot(g,fd)` も streak の5点平均も fd と −fd で同じ。「来る」と「戻る（引き波）」を区別できない。
3. **越流前は何も起きない**。`over_300s/700s`。海は流速0.3m/s未満で fast=0、筋もうねりもなし。上昇は5m/600s≒0.8cm/sで見えない。実測（seq、704→766秒＝実3秒）も差なし。到達まで×20で約35秒待つが、天端まで何cmかの手がかりがない。
4. **先端が読めない**。`pin_700s` の縁は灰色で薄い（edge は sp>0.3 のみ、縁は a で透過）。`swe.js` 376行は h<0.01 で u,v=0 なので、先端セルの流れが消える。
5. **色が近く厚みも不明**。`over_1100s` は濁流と濡れ地面が同系の茶。建物の水位線は最大値（env.w）だけで、いまの水位線がない（world.js 545）。

## 2. 直し方
**(a) 流れ粒子（最優先）** 飛沫バッファは弾道・寿命1秒で用途が違う。別に持つ：`world.js` に `flowMarks`、`swe.js` に `markUpdate`（PC 2^16、スマホ 2^15、vec4＝x,z,年齢,乱数）。
- 更新：R2 の (u,v) を双一次で読み、RK2で移動。年齢は画面の秒で3〜5秒。
- 再配置：寿命・陸（乾き）・遅い(sp<0.15)で、乱数セルを最大4回試し、**濡れて sp>0.3 のセルだけ採用**（密度は流れの速い所に集まる）。先端付近（h<0.3）を厚めに。
- 進め方：**計算の時間 × min(再生速度, 20)**。×60以上は頭打ちで、先端と食い違うのは最速だけ。
- 尾：長さ＝sp×6秒（計算の時間）＝「水が6秒で進む距離」。幅は max(0.4m, 視点距離×0.003)。頭が明るく尾が細く消える（向きの符号が出る）。水面に寝かせる（y=η+0.05）。
- 流れマップは min(速度,4) に抑え、T=1.5秒に（変位を8m以内に）。

**(b) 先端** 濡れ乾きの境に、幅0.4〜0.8mの細く明るい縁の線（計算した境そのもの）。矢印は付けない（粒子と二重になり先端の位置を隠す）。前提：先端セルのu,vを残す（氷室さんへ）。

**(c) 流れの速さ** 色分けを排他の選択に（なし／深さ／流れの速さ）。`uEnv.w` を0/1/2に。2は粒子を sp で着色（〜0.5・1・2・4・8m/s、凡例つき）。危険度の言葉は付けない（水深×流速の目安は出典未確認）。矢印の格子は作らない。

**(d) 厚み** 建物の壁に「いまの水位線」（surfTex の drawH で `|hLocal−h|` を細い線に）。俯瞰の既定は仰角約30度、距離約250m。方位は最大流速の向き（鳴海さんと調整）。

**(e) 引き波** 粒子は逆向きに流れるだけで自動。ドックに「押し／引き」の文字（水位の増減）。

**(f) 時間** 防潮壁の天端までの「あと○m」を海側に表示（計算値）。越流の開始（`coast.breached`>0 または先端が壁に到達）で×5に自動で下げ、「水が防潮壁を越え始めました。速度を×5にしました」と出す。×60→×5を戻せるように。

## 3. うそにならないか
- 漂流物・砕ける波は描かない。粒子は**丸い塊にしない**（前回レビューで漂流物に見える指摘）。細い線だけ。乾いた所・壁の中には出さない。
- 凡例：「白い細い線＝水の流れの向きと速さの目印です（計算した流れから描いた印で、波や漂流物ではありません）。頭が明るい側へ進みます。長いほど速い。早送り中は、動きを見やすくするため線の動きを遅めにしています」。
- 越流前は「海の高さが上がっています。変化は小さく見えます」。

## 4. 重さ（未測定の見積り）
粒子更新は6.5万スレッド×読み4回、0.05ms未満。描画は6.5万の細い板、PC+0.3ms、スマホ(2^15)+1ms前後。現状の水の描画は1.0〜1.5ms（bench.txt）なので60fpsは保てる見込み。実測は `water.mjs` で。段階：`mesh.count` を fps 連動で 65k→32k→16k→8k（既存の prScale と並べて）。距離で間引く。

## 5. 控えめ・動きを減らす
控えめ表示と `prefers-reduced-motion` では粒子を止め、**40m間隔の固定の矢印**（約1,400本、2秒ごとに更新、点滅なし）に置き換える。流れの向きの情報は消さない。自動再生の抑止（`reduceMotion`）は今のまま。

## 6. 優先順位とやらないこと
1. 流れ粒子（a）と時間のものさし。2. 見どころで自動減速と「あと○m」（f）。3. 先端の線と、いまの水位線（b・d）。4. 流れの速さ表示（c）。5. 俯瞰の既定の見直し。

やらない：漂流物・巻き波・先端の矢印・等時線（到達時刻に読まれる）・水を粒子で描くこと。
