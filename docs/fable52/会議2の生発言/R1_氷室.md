# R1 氷室 朔（B 計算／A のうち計算由来）

ソースは無変更。GPU で追加実測を1回だけ行った（試験用スクリプトは作業フォルダのみ）。

## 0. 実測したこと
- ダム崩壊（Ritter）を格子 N=256/512/1024（dx=2/1/0.5m）で。中央水深 0.877/0.883/0.886（理論 0.889）、x=40m で 0.178/0.172/0.170（理論 0.169）。先端は 1cm 線で −16.5/−14.1/−9.7%、5cm 線で −9.5/−3.1/+2.1%。**「先端14%遅れ」は水深1cm という薄膜の検出位置の問題で、格子を細かくすると縮む**。波の本体は合っている。直す対象ではない。
- 海浜試験（T3）を、1回の進め方（10/30/100/300 サブステップ）だけ変えて4回。gain 0.577/0.575/0.576/0.608、岸の水位 3.24/3.24/3.26/3.36m（入力3m）。**同じ条件で最大3.5%ぶれる**。アプリでは読み戻しの届く時刻と再生速度も効くので、1〜2割という報告は妥当（アプリ内は未測定）。

## 1. 誤った印象を与える点（上位5つ）と直し方
**① gain が読み戻し依存（swe.js 511–551、494）**　6フレームごとに非同期で受け取り、届いた時点で更新するので、結果が実時間・再生速度・fps に左右される。
直し：制御を GPU 内で閉じる。`coastProbe` の和・最大から gain を更新する1スレッド kernel を足し、実行は「サブステップ番号がM（例150）の倍数」で決める（ホストで compute 列を分割。uniform を間で更新）。stage2 は uWave.x に shape(t)·(H−tide) を受け、gain は buffer から読む。CPU 側の読み戻しは表示専用にして制御へ戻さない。
数字：期待値は不変、ばらつきが消える。確認：batch 10〜300・速度×1/×20/×60 の12通りで gain の差 <0.5%、岸の水位の差 <1%（現在3.5%）。T1〜T3 合格。重さ：probe は近岸帯のセル数（数千〜数万）を150ステップに1回。無視できる。

**② 入力＝単峰＋満水位を900秒保持、岸の平均水位を H に合わせる（472–489、537–551）**　最大水位の包絡を作る。実際は振動するので、深さ・浸水の長さは深め（安全側だが「公式に合う」のではない）。名古屋再現1.7m対公式1.27mの一因（残りは③④⑤と地殻変動の有無＝未確認）。
直し：形は変えず、感度実験で量る。hold 900→300秒、gain 上限、で点の最大深さがどれだけ動くか。15%超なら表示に「最大水位の継続時間を長く仮定」を出す。第2波は前回決定どおりやらない。

**③ 鏡像壁の縁と1.5km箱、造波帯が箱の中（195–202、42–83、plan.js baseL）**　陸側・横の縁は「外も同じに浸水」の壁。水が出ていけず、戻る波と溜まりで深く出る方向（自由流出の逆の偏り）。沿岸点では造波帯200mが箱の1/7を占め、岸まで数百mしかない。
直し：まず感度実験（同じ点を L=1.5km と 3km で。Δ最大深さ）。差が20%超なら、内陸用の二段（nest）を沿岸点にも使う。既存機構の流用で、広域は粗格子なので重さは +20〜30% 見込み（未測定）。今日は実験のみ。

**④ 越流破堤＝5cmで即・地盤まで（429–437）**　3セル幅の帯が一撃で消え、全水頭のダム崩壊が起きる。実際の破堤は分〜時間で広がる。到達が早く、最初の流速・深さが大きい方向。内閣府・愛知の条件と同じというのは docs/04 の記述で、一次は再確認していない。
直し：破堤を時間関数にする（天端が毎秒 v_e だけ下がる。v_e は「即時」を既定のまま、遅い版で感度を見る）。越流前の流量は、静水圧再構成の HLL が既に堰として働く。本間の式（q=0.35h√(2gh)）との照合を1ケースやる（式は記憶、一次未確認）。

**⑤ 建物＝1セル壁、海底は合成（region.js 171–181、223）**　2mより狭い路地は閉じるか2m水路になる。海底は gain が吸収するので深さには効かないが、港の固有周期・屈折は偏る。JODC 500m 水深などの実データは入手と規約が未確認。今回はやらない。
その他（低位）：速度上限15m/s、ネスト縁70m、固定 dt（実効 CFL は約0.1）は、この範囲では誤印象の主因ではない。dt の係数 0.3→0.4 で ×1.3 の余裕が取れる（T1〜T3 と質量で確認してから）。

## 2. 検証の追加（tests.js）
Thacker の放物面（乾湿境界の移動、解析解）で水深の L2 誤差 <3%・質量誤差 <1e-6、Synolakis の 1:19.85 斜面（孤立波の遡上、NTHMP BP4、データ入手は未確認）で遡上高の誤差 <10%、Ritter は 5cm 線 <10% に基準を直す。基準値は私の提案。

## 3. 巻き込む波・漂流物・落ち込み
やらない。浅水方程式は水面を1枚の高さで解くので、巻き込みは出ない。段波の前面は衝撃波として HLL が捕える（砕波の消散を含む）ので、波形と格子で出る。漂流物は検証済みの模型がなく、数字に見えるので描かない。防潮壁の落ち込みは、既存の越流流量に飛沫（フルード数・水位差で出す）を描画側で足す。計算は触らない。

## 4. 入力の波形：「押し寄せる感じ」の原因
計算では先端が鈍る主因ではない。根拠3つ。(a) 沖の山が600秒で上がると、1.5km箱の中で段波になる前に岸へ着く（衝撃波化距離 ≈ (d/1.5a)·c·T ≈ 20〜30km、T=60秒でも2〜3km）。(b) 内閣府2025（docs/fable52/05）港区は +1m に95分、+3m に114分。約2m／19分＝1.75mm/s（最短どうしの差なので目安）。こちらの 0→H は約6mm/s で、名古屋では**公式より急**。緩いのが原因ではない。(c) 再現の水位は、堤防を越える瞬間まで動かない（名古屋 t=300s で水先端まで約100m、700sで約40m＝約0.15m/s）。そのあと破堤で速くなるのに、×20 再生だと1秒に80m動き、ぼやける。
結論：波形は急にしない（偽の段波と港の揺れを生む）。直すのは再生：水先端が点から300m以内（probe の `coast.front` が既にある）で速度を×5まで自動で落とす。これは main.js の frame だけ。
地域別：内閣府 ichiran.pdf の「+1m と +3m（または最大）の到達時間差」から rise を決める案（下限300秒）。高知・尾鷲の値は未読で未確認。津波水位の時系列を公表しているかも未確認。
