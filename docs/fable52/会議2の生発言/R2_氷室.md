# R2 氷室 朔

## 1. 反論
**オルテガ (f)「防潮壁の天端まで あと○m を海側に表示」に反対。** 天端（名古屋は+4.6mの仮定）も岸の水位（gain で H に合わせた値）も入力で、差は計算結果ではない。「あと0.8m」は余裕に読まれ、「到達せず」と同じ誤読を生む。出すのは「海面は仮定した高さまで上がっています」まで。越流時の減速は賛成。

**三枝「続く」を一つの段階として、等幅の帯に置く案に条件。** 900秒の保持（swe.js 472）は最大水位の包絡をとる仮定で、実際の波ではない。「続く（仮定）」とし、長さは言わない。

**鳴海「注視点を計算範囲 ±L/2 に挟む」に反対。** 二段計算では水は箱の外から来る。main.js:432 は広域L×1.5まで見せる設計で、±L/2 では広域視点が潰れる。挟むのは描画する最大の正方形にする。

## 2. 質問への答え
**オルテガ**
- 先端の u,v：残せる。swe.js 376 は h<0.01 で u=0 にしているだけ。`hu/max(h,0.03)` を3×3でならす。`hu/(h+0.05)` は h=0.02 で真値の3割に落ちるので避ける。
- 最大流速の向き：残せる。M は4成分とも使用済みなので、新バッファ D（最大時の u, v、水位変化率）を足し、aux kernel（swe.js 279）で sp>m.z のとき更新。768²で +9.4MB。
- 水位変化の符号：全体は etaTarget の傾き（押し・保持・引き）で決定的に。点は D の水位変化率（5秒の指数平均）。

**鳴海 浸水の境の線** 水深 **5cm** の等値線。1cm 線は格子で動く。幅は2m以上。第2線は **30cm**（内閣府の到達判定、docs/fable52/05）。時刻は付けない。

## 3. 議長の問い
**(a)** 遅くするだけでは不満は消えない。「来る」と読める絵（流れの印と先端）が要る。オルテガの粒子案を支持。計算側で、感度実験なしに今日約束できるのは次だけ。
- gain とバッチ幅の決定論化（下記 (b)）。数字の向きは不変、ばらつきが T3 の3.5%（アプリは1〜2割）から1%未満へ。
- 先端 u,v・最大流速の向き・水位変化の符号（上記）。数字は変わらない。
約束できない：造波帯・鏡像壁・破堤の変更。以下は推定で実測なし。
- 沿岸点を二段（nest）に：最大深さ 0〜−20%、流速 ±15%。
- 破堤を60〜180秒で広げる：最大深さ ±5%、最初の流速 −20〜−50%、到達は遅れ分だけ後ろへ。

**(b)** 採るのは単純案。GPU案の危うさ：①列の分割と途中の uniform 更新（呼び分けの負荷は未測定）、②和が uint 量子化（1cm）で近岸が−0.5cm偏る、③読み戻しと制御 kernel の二重化。単純案は同じ制御則のまま。実装：step() を**固定チャンク（16サブステップ）**で進め、各チャンクの先頭で uWave を更新（今は「バッチ全体で一定」で、バッチ幅が第2のぶれ要因）。制御は「サブステップ番号が M（シミュレーション15秒ぶん）の倍数」の点だけで、probe を await して適用する。待つ間 step() は何もしない（main.js:1066 の `Math.max(1,…)` に注意）。止まりは1〜2フレーム、×20 で約1秒に1回（fps への影響は未測定。`water-bench.mjs` で確認）。これで再生速度・fps は結果に影響しない。

**(c)** 決めるのは `autoSpeed()` 1つ（main.js）。利用者のボタンは「上限」で、自動は上限より下げるだけ。規則：①越流（`coast.breached`>0）か、先端が300m以内→×5。②点に水が着いて60秒（計算の時間）後、または先端が消えたら上限へ。③利用者が押したら上限を上書き。三枝の1行と帯は同じ状態の列挙（静か／上昇／越流／陸浸水／到達／保持／引き）から作る。文言は「水が近づいたので×5にしています［戻す］」。

**(d)** 前後の表：名古屋港ガーデンふ頭（H=5m・潮位1.2m・壁4.6m・768²）を t=300, 700, 1100, 1750s（`water/before_report.json` と同じ）、高知を400, 800s、内陸（富田町）を1500s。列：深さ（いま）・最大・最大流速・先端の距離・gain。**前は各5回**測って幅で載せる（前もぶれるため）。合格：①T1 質量誤差<1e-6（現5e-10）・流速<1e-3、T2 中央水深±0.02、先端は5cm線<10%、T3 ±25%（現8%）。②再実行：batch 10〜300・×1〜×60 の12通りで、gain の差<0.5%、最大深さの差<2%。③公式比（ガーデンふ頭 1.27m）：現行比（1.35〜1.4）より離れないこと。④fps：現状（60／59）から3以上下げない。

## 4. 譲る点・譲らない点
**譲る**：「計算が主因でない」は言い過ぎだった。計算側が出すべきデータ（先端・向き・符号）があり、出す。契機に越流を加える。
**譲らない**：波形は急にしない（名古屋は公式の約1.75mm/sに対し約6mm/sで、すでに急。docs/fable52/05）。「あと○m」と到達時刻は出さない。漂流物・巻き波は描かない。破堤の既定は即時のまま。
