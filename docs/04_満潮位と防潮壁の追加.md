## 実装

1. **初期潮位**
   - 海のセルは「はじめの潮位」から始まる。
   - 目標水位は `η(t) = 潮位 + gain·(H − 潮位)·形`。公式の津波高 H は満潮位を含んだT.P.基準の値なので、波の分は H − 潮位 になる。
   - 地域ごとの既定値：
     - 名古屋港：T.P.+1.2m
     - 愛知県の他地域：T.P.+1.0m
     - それ以外：0m。画面に「満潮位は未確認」と表示する。
2. **防潮壁の位置**
   - 国土地理院ベクトルタイルの次の線を使う：
     - 海岸線「堤防等に接する部分」（5103）
     - 河川「堤防等に接する部分」（5203）
     - 水門（5515、閉鎖とみなす）
   - これらの線の陸側の岸セルに天端を与える。水のセルは嵩上げしない。
   - 名古屋港の範囲では既定でONにし、天端 T.P.+4.6m（公表範囲の低い方）とする。範囲外ではOFFとし、ONにしても仮の値だと明記する。
3. **越流破堤**
   - 天端を越えた水（堤防セルの水深 5cm 超）があると、そのセルは地盤まで下がる。
   - 内閣府・愛知県の想定と同じ条件。チェックを外すと「壊れない」を選べる。
4. **表示**
   - 防潮壁はセルごとのインスタンス箱で描く。高さはGPU上の地盤値をそのまま読むので、壊れたセルはその場で消える。
   - 最初に壊れた瞬間を通知し、結果画面に条件（潮位、天端、破堤したセル数）を表示する。
5. **不具合の修正**
   - 堤防のない町で、破堤カウンタの読み戻しが一括読み出し全体を失敗させ、海岸水位の制御が止まっていた。
   - 制御の速度が再生倍率に依存していた。シミュレーション時間あたりの速度に変更。
   - 押し波の立ち上がり中は、伝播の遅れがあるので上げ方向に補正しないようにした。

- 公式（内閣府2025 ケース01、100m集約）：1.27m
- 防潮壁と潮位を入れる前（2周目の終了時）：2.07m
- 公式との差は縮んだ。残る差の主な理由は、防潮壁の位置と入力波の形と考えられる。
  - 位置：実際の防潮壁は岸壁より内陸側にある区間があるが、今回は岸の線に置いている。
  - 形：入力波は一様な長波にしている。
- 善進本町（格子1216²）：
  - 潮位だけで水をかぶるのは、防潮壁の外にある低い所 0.03km² だけ。
  - 約12分後、防潮壁 5,440 セルのうち 2,681 セルが越流して壊れた。
  - 約25分後の陸の浸水は 1.63km²。地点には届かず、公式でもこの地点は浸水セルなし。
- 単体テスト3本は、変更後も合格。

- 沖の高潮防波堤：計算範囲の外にある。海岸の津波高を境界条件として使っているため、その効果は H に含まれているとみなす。
- 河口堤防の天端高：未確認。

## 不具合修正：2回目に選んだ地点が真っ黒になる（2026-09-24、あきらパパ様の報告）
- **症状**：1回目の地点は表示されるが、「地点を選び直す」で開いた2回目は3D画面が真っ黒になる。HUDと時計は動いている。
- **原因**：three.js の `Sprite`（飛沫の粒子）は、全インスタンスが1つのジオメトリを共有している。1回目の町を片付ける処理でそのジオメトリまで dispose していたため、2回目の飛沫が破棄済みのGPUバッファを参照した。その結果「Buffer used in submit while destroyed」になり、そのフレームの描画がまるごと失敗していた。
- **切り分け**：片付けの処理を1つずつ外して、エラー件数を数えた。
  - ソルバーを外す → 596件
  - 影を外す → 592件
  - パスを外す → 598件
  - マテリアルを外す → 604件
  - **ジオメトリを外す → 0件**
- **修正**：片付けで Sprite のジオメトリだけは dispose しない（`world.js`）。
- **確認**：ヘッドレスChromeで 名古屋港 → 東海市 → 善進本町 と3回続けて切り替え、GPUエラー0件、3回とも表示されることを確認した。
- **あわせて修正**：東海市にも名古屋港の防潮壁（T.P.+4.6m）が既定で入っていた。確認済みの26.4kmは天白川河口〜庄内川河口（名古屋市の熱田・中川・港・南区）なので、判定を区コードに変更した。東海市は潮位 T.P.+1.0m・防潮壁なしが既定になる。
